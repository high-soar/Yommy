## 6. プロセス・ガイドライン・スキル改善アクション（Kaizen 5 施策）

`v1.3` で検出された連続スクロール実ブラウザ計測差異・Push/Pull 非対称・一覧フック離脱漏れ・テスト分離/IT 待機・双方向トレーサビリティ不備の再発を恒久防止するため、[docs/guidelines/testing.md](../../guidelines/testing.md)（`§3.11`）および [.github/skills/c-ut-workflow/SKILL.md](../../../.github/skills/c-ut-workflow/SKILL.md) へ以下の **5 施策** を反映しました。

1. **連続スクロール実ブラウザレイアウト計測・`chapterIndex` 再計測依存配列・`updateBookmark` DB 時刻同期（`No. 503, 505, 513, 525`: `R1-20` 再発防止）**:
   - 横書き（`horizontal-tb`）および縦書き連続スクロール（`scroll`）において、スクロール対象内側コンテナ（`reader-content`）へ不要な `h-full` を強制して子要素上下マージン（`my-6` 等）のマージン相殺や固定高コンテナ超過（`scrollHeight > clientHeight`）を起こさないこと（縦書き時のみ `h-full w-full`、横書き時は `w-full` とし、1 画面短文 `maxScroll <= 0` 自動完了を実ブラウザ IT で確認する）。
   - キャッシュ済みエピソード間遷移（`TR-05`）では `<ReaderView>` がアンマウントされず同一 `bodyHtml` / `initialScrollProgress` で話数のみ変化するため、組版・短文計測 `useEffect` および初期スクロール位置復元 `useEffect` の依存配列に `chapterIndex` を必須とする。
   - `useReader` の `updateBookmark` 実行後は `new Date().toISOString()` の別生成（`T_mem > T_db` スキュー）を避け `novelRepository.getNovelById` の DB 実値へ同期（`await` 後 `isMountedRef.current` ガード維持）し、`Date.parse` 時刻比較には `Number.isFinite` / `Number.isNaN` ガードを設ける。
2. **クラウド同期 Push/Pull 対称マージ・データ型整合（`No. 504, 511`: `R1-18` 再発防止）**:
   - `SyncEngine.mergeNewNovel` / `mergeExistingNovel` / `buildMergedSyncNovels` において、Pull 側と Push 側の双方で同一のビジネス不変条件（`mergedTotalChapters > winner.totalChapters` かつ勝者が旧最終話末尾到達済みなら `winner.totalChapters + 1`, `progress = 0.0` へ進行、かつ `lastReadAt` 維持）を対称実装する。
   - `SyncNovelData` 等の後方互換オプショナルフィールド追加時は、旧形式（`undefined`）のフォールバック規則（別話数時 `0.0` vs 同一話数時ローカル進捗維持）を実装・UT・`architecture.md` で 1 対 1 に定義する。
3. **一覧・探索フックのアンマウント後遷移遮断 ＆ `useRef` 連打排他ガード・動的サイト表示（`No. 512, 515, 516`: `R1-13, R1-14, R1-19` 再発防止）**:
