# Milestone `v0.5`（縦書きリーダー組版・ページめくり抜本改善・カスタマイズUI・キャッシュ管理）品質分析・振り返りレポート（Kaizen）

## 1. エグゼクティブサマリー（Executive Summary）

Milestone `v0.5`（Reader Pagination Refinement & UX Expansion）では、Milestone `v0.4` で実装されたページめくり・クラウド同期基盤を基点とし、実機検証（`HO-23`）で判明したリーダー画面の致命的課題（スワイプ不発・文字途切れ・総ページ数欠損）および機能拡張要望（フォント・余白カスタマイズ、キャッシュ管理）に対応する 3 つの主要機能 Issue（#168, #169, #170）を Issue 駆動マイクロウォーターフォール（① 要件確認 → ② 設計更新 PR → ③ 製造 MK Sub-issue PR → ④ 結合テスト IT PR）に沿って完遂した。

1. **Issue #168（リーダーのページめくり・スクロール実機不具合修正と横書きスクロール限定化、HO-23）**：
   - Android WebView におけるタッチイベント制御（CSS `touch-action: none` / Tailwind `touch-none`）を実効 `paged` モードへ適用し、ネイティブジェスチャー奪取（`pointercancel`）によるスワイプ不発を根絶。
   - ブラウザ標準の縦書き CSS マルチカラム組版（`writing-mode: vertical-rl`、`columns: 1`、`column-fill: auto`、`column-gap: (pageMarginPx * 2)px`）および `translateY` 確定変位を導入し、画面端での文字・ルビ・傍点の縦切断・分割描画を完全に防止。
   - マルチカラムの `scrollHeight` に基づく総ページ数（`totalPages`）計測アルゴリズムを導入し、しおり復元時やエピソード遷移直後、2ページ目以降のリサイズ時にも総ページ数が欠損・縮小しない安定化を実現。
   - 横書き表示時は連続スクロール固定とし、設定画面（`SCR-05`）のページ送りモードセレクターを「ページめくり（縦書き時）」「連続スクロール」の 2 択に整理。本文先頭・末尾の前後話ボタンおよび端到達後の 2 段階スワイプ/タップ操作（ヒントトースト表示・2.5 秒以内再操作で前後話遷移）を整備。
2. **Issue #169（フォント種別と画面余白のカスタマイズ UI およびリーダー組版反映、SYS-REQ-09 拡張）**：
   - 設定画面（`SCR-05`）にフォント種別 5 種（UD明朝、明朝、UDゴシック、ゴシック、Klee教科書体）のドロップダウンセレクターと、画面余白（`8〜48px`、4px 刻み、初期値 20px）のステッパーボタンを新設。
   - `SampleTextPreview` およびリーダー画面（`SCR-03`）のハードコードスタイル（`font-serif`、`p-6`）を廃止し、動的フォントスタックおよびインライン余白スタイルを適用。マルチカラム組版の段幅・段高・カラム間隔を余白に応じて動的再計算。
3. **Issue #170（キャッシュデータ容量の可視化と既読/本文キャッシュ削除機能、SYS-REQ-05 拡張）**：
   - 作品詳細画面（`SCR-02`）ヘッダーにキャッシュ容量表示（例: `全 12 話（取得済み 8 話 / 1.2 MB）`）と「本文キャッシュ整理」アクションを追加し、目次・既読・しおりを保持したまま既読話のみ／全話の本文キャッシュ削除・容量即時再計算を提供。
   - 設定画面（`SCR-05`）に「ストレージ・キャッシュ管理」セクション（`StorageCacheSection`）を新設し、アプリ全体の合計キャッシュ話数・容量の可視化と全体一括削除機能を提供。

全機能 PR マージ後、**Issue #171（Milestone `v0.5` 全体横断レビュー・品質分析・完了承認）** において、マルチモデル 4 オーケストレーター（`Gemini 2.5 Flash` / `Gemini Pro` / `Claude 3.5 Sonnet` / `Copilot SDK in VS Code`）による多角的・独立な節目横断レビューを実施し、全 27 件（`R1-01`〜`R1-27`）の指摘事項を検出した。
Step 2 において全 27 件の是正（キャッシュ削除時の `updated_at` 保持によるクラウド同期 LWW 整合性保証、実効 `paged` モードでの native scroll ガード、WebView 連続スクロールでの Pointer/Touch 参照分離、ダイアログアクセシビリティ・アンマウント保護、正本仕様書・OKF メタデータ同期、実機申し送り `HO-15`〜`HO-25` の証跡整理、Playwright IT アサーション拡充）を直列に完遂し、さらにマージ後の実機動作確認（`R1-28`, `R1-29`）において検出された右綴じ縦書きリーダーの組版・スワイプ方向（3 スロット水平スワイプラック・スロット内マルチカラム組版・左から右スワイプでの次ページ進行）を抜本是正した。静的チェック・単体テスト 100%・Storybook VRT 400 件・Playwright IT 12 件すべて PASS を達成した。

## 4. Milestone `v0.5` 固有の設計的知見と課題（Architectural Learnings）

### 4.1 ローカルキャッシュ削除とクラウド同期不変条件（Invariants）の保護（`R1-01`）

- **知見**: ローカルストレージの容量整理（本文キャッシュの破棄）は「端末内の一時データの消去」であり、「作品メタデータ（タイトル、あらすじ、しおり、既読状態）の更新」ではない。
- **教訓**: `chapterRepository.deleteCachedBodies` および `deleteAllCachedBodies` において、`cached_chapters` と `total_byte_size` は最新集計値へ更新するが、**`novels.updated_at` は更新してはならない**。`updated_at` を進めてしまうと、他端末で削除された作品の Tombstone 比較（`remoteDeletedAt > max(created, updated)`）が逆転し、削除済み作品がゾンビ復活してしまう。以後の機能拡張においても、「ローカルキャッシュ変更」と「同期対象メタデータ変更」の更新タイムスタンプ責務を厳格に分離する。

### 4.2 モバイル WebView における PointerEvent と TouchEvent の共存設計（`R1-27`）

- **知見**: Android WebView において、`touch-action: none` が指定されている実効 `paged` モードでは PointerEvent が最後まで追従するが、ネイティブスクロールが有効な `scroll` モードでは指移動開始後数ピクセルでブラウザに制御が奪われ `pointercancel` が発火する。
- **教訓**: `useReaderGestures` において PointerEvent 用の座標保持（`pointerStartRef`）と TouchEvent 用の座標保持（`touchStartRef`）を単一の ref で共有していると、`pointercancel` が TouchEvent の開始座標まで消去してしまい、`AC-RD-19` の端部到達後 2 段階スワイプが不発となる。**PointerEvent と TouchEvent はライフサイクルが異なるため、内部 state/ref を完全に分離する**。

### 4.3 ページめくりモードにおける DOM `scroll` イベントの完全隔離（`R1-22`）

- **知見**: 実効 `paged` モードでは `overflow-hidden` コンテナ内で `translateY` によりページ送りを行うが、スクロール位置リセット（`scrollLeft = 0; scrollTop = 0;`）や DOM フォーカス移動によってブラウザがネイティブ `scroll` イベントを非同期発火させることがある。
- **教訓**: `ReaderView.tsx` の `handleScroll` は連続スクロールモード専用とし、冒頭に `if (isPaged) return;` ガードを設ける。さもなければ `scrollLeft === 0` が進捗 `0.0` と評価され、読書中のしおり進捗が先頭へ上書き巻き戻る重大な退行を招く。

### 4.4 結合テストにおける `page.reload()` 後の決定論的待機義務（`R1-24`）

- **知見**: Playwright テストにおいて `page.reload()` を実行した直後は、ブラウザの DOM 構築と React マウント、および非同期 SQLite / Service 初期化（`window.__yommyServices.isReady`）の完了タイミングにレースコンディションが存在する。
- **教訓**: `page.reload()` 直後は、DOM 要素探索を開始する前に必ず `await page.waitForFunction(() => typeof window.__yommyServices !== "undefined" && window.__yommyServices.isReady === true)` を呼び出すことを徹底する（テスト順序の逆転防止）。

### 4.5 右綴じ縦書きリーダーにおける水平スワイプラックとマルチカラム組版の確立（`R1-28`, `R1-29`）

- **知見**: 縦書きリーダーにおいて、ページめくりアニメーションを縦方向（`translateY`）で行うと「下のページがせり上がる」不自然な挙動となり、また `columns: 1` を撤廃して単純な `height: 100%` とすると行・文字切れが再発する。さらに紙の日本語書籍（右綴じ）は「左から右へめくって次ページへ進む」メンタルモデルである。
- **教訓**: 3 スロット水平スワイプラック構成（`writing-mode: horizontal-tb; left: -pageWidth + slideOffsetPx`）を採用し、各スロット内に CSS マルチカラム（`columns: 1; column-gap: (pageMarginPx * 2)px`）と静的 `translateY(-(slotPage - 1) * pageHeight)` を適用することで、行・文字切れを根絶しつつ、縦アニメーションを 0% に排除して自然な水平ページめくり（左から右スワイプ `dx > 0` で次ページ）を実現した。
