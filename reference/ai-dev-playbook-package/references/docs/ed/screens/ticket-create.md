## 1. 画面概要

- **画面 ID**: SCR-03
- **画面名**: 問い合わせ新規起票画面
- **目的**: 一般ユーザーが、自プロジェクトに紐づく新たな問い合わせ（質問・障害報告・作業依頼等）を登録し、チケット管理ライフサイクル（起票 → 閲覧 → 対応更新 → 完了）の起点として迅速な対応ワークフローを開始する。
- **対象利用者**:
  - **一般ユーザー専用（業務運用担当者）**: 自プロジェクトに属する新規チケットを登録する。
  - ※**管理者ユーザー（システム管理者）はアクセス不可**: 管理者ロールはプロジェクト運用業務を行わないため、本画面の利用対象外となります。管理者が直接 URL（`/tickets/new`）へアクセスした場合は、Role Guard によりアクセスを拒否し、安全な初期ポータルであるダッシュボード（SCR-00）へリダイレクトした上で、権限エラー通知を表示します（TR-17）。
  - ※**未認証ユーザーはアクセス不可**: ログインしていない状態で本画面へアクセスした場合は、Auth Guard によりログイン画面（SCR-AUTH: `/login?redirect=%2Ftickets%2Fnew`）へ強制リダイレクトします（TR-06）。
- **想定 URL パス**: `/tickets/new`（Next.js App Router: `src/app/(authenticated)/tickets/new/page.tsx`）
- **画面共通レイアウト**:
  - 本画面は認証保護された業務画面であり、Next.js App Router の共通レイアウト（`src/app/(authenticated)/layout.tsx`）が適用されます。画面左側に開閉式サイドバー（展開幅 約240px / 折りたたみ幅 約60px / モバイル幅ではオーバーレイドロワー）を配置し、ヘッダーにシステム名、ログインユーザー情報、ログアウト導線を提供します。

### 3.4 画面離脱防止（Dirty State ガード）コンポーネント

### 3.5 共通ナビゲーション（開閉式サイドバー）部

- **開閉トグル**: 右上の `←` / `→` ボタンで展開（240px）↔ 折りたたみ（60px）を切り替え。開閉状態は `localStorage` に保持（TR-21）。
- **メニュー項目（一般ユーザー用 3 枠）**:
  - 1. 📊 ダッシュボード（SCR-00）
  - 2. 📋 問い合わせ一覧（SCR-01）
  - 3. ➕ 新規起票（SCR-03）: **本画面表示中はアクティブ（選択中ハイライト）表示**。
- **ユーザー情報 & ログアウト**: ログイン中の一般ユーザー表示名、ロール（一般）、所属プロジェクトを表示。ログアウトボタン押下時はセッションを破棄して SCR-AUTH ログイン画面へ遷移（Dirty State ガード対象）。

## 4. 操作および振る舞い仕様

| 操作 ID | 対象コントロール                 | 操作内容                                               | 画面の振る舞い                                                                                                                                                                                                                                                                       |
| ------- | -------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| OP-01   | タイトル入力欄                   | 文字列を入力する                                       | タイトルの入力値を state に反映する。文字数が 1 文字以上の場合は Dirty State を有効化する。未入力エラーが表示されている場合、入力開始時にエラー表示を即時クリアする。                                                                                                                |
| OP-02   | 所属プロジェクトセレクター       | プロジェクトを選択する（複数所属時）                   | 選択されたプロジェクトを state に反映する。Dirty State を有効化する。未選択エラーが表示されている場合はクリアする。選択プロジェクトに応じて担当者候補リストを再取得・フィルタリングし、担当者セレクターの選択肢を連動更新する。                                                      |
| OP-03   | 担当者セレクター                 | 担当者を選択する（または未設定に戻す）                 | 選択された担当者（または null）を state に反映する。初期値（未設定）から変更された場合は Dirty State を有効化する。                                                                                                                                                                  |
| OP-04   | 問い合わせ本文テキストエリア     | 文字列を入力する                                       | 本文の入力値を state に反映する。残り文字数をリアルタイムに更新する。文字数が 1 文字以上の場合は Dirty State を有効化する。未入力エラーが表示されている場合、入力開始時にエラー表示を即時クリアする。                                                                                |
| OP-05   | 「起票する」ボタン               | クリック / タップする                                  | 全入力項目に対してバリデーションを実行する。<br>・**検証失敗**: 最初のエラー項目にスクロール・フォーカスし、各項目の直下にエラーを表示する。API 送信は行わない。<br>・**検証成功**: 起票 API を送信し、ボタンを非活性化する（OP-06 へ）。                                            |
| OP-06   | 起票処理実行（API 通信）         | `POST /tickets` API 呼び出し                           | 通信中はボタン内にスピナーを表示し二重送信を防止する。<br>・**成功時 (201)**: Dirty State を即時解除し、作成されたチケットの SCR-02 問い合わせ詳細画面（`/tickets/[id]`）へ自動遷移する（TR-14）。完了トーストを表示。<br>・**失敗時**: エラーメッセージを表示し入力内容を保持する。 |
| OP-07   | 「キャンセル」ボタン             | クリック / タップする                                  | 入力内容が存在する場合（Dirty State 有効）は離脱確認ダイアログを表示する（OP-09）。未入力または変更なしの場合は、直ちに SCR-01 問い合わせ一覧画面へ遷移する（TR-15）。                                                                                                               |
| OP-08   | 画面離脱操作                     | サイドバーメニュー、パンくず、ログアウト、ブラウザ戻る | 入力内容が存在する場合（Dirty State 有効）は遷移を一時中断し、離脱確認ダイアログを表示する（TR-08, TR-18, OP-09）。未入力の場合は直ちに目的画面へ遷移する。                                                                                                                          |

## 6. ロール別認可ガード（403）および画面離脱防止（Dirty State）仕様

### 6.1 管理者アクセス時の認可ガード（Role Guard / 403 フォールバック）

1. **アクセス制御の背景**:
   - 業務上の責務分離（SoD: Separation of Duties）に基づき、管理者ユーザーはプロジェクトの日常業務運用（チケットの起票・更新・コメント対応）を行わず、システム全体の設定・監査に専念します。
   - したがって、SCR-03 問い合わせ新規起票画面は**一般ユーザー専用**であり、管理者ユーザーの利用は禁止されます。
2. **振る舞い仕様**:
   - ルーティング解決時、認証セッションからロール（`currentUser.role`）を確認します。
   - `currentUser.role === 'admin'` のユーザーが `/tickets/new` にアクセス（直接 URL 入力、ブックマーク等）した場合、本画面の描画を行わず直ちにブロックします。
   - 独立した味気ない 403 エラー画面でユーザーを孤立させることを防ぐため、管理者ユーザーの安全なホームである **SCR-00 ダッシュボード（`/dashboard` または `/`）へ即時フォールバックリダイレクト（TR-17）** します。
   - 遷移後のダッシュボード画面上部に、「**管理者ロールでは新規起票機能は利用できません（403 Forbidden）**」という警告トーストまたは通知アラートを表示します。

### 6.2 画面離脱防止（Dirty State ガード）

1. **Dirty 状態（未保存変更あり）の定義**:
   - 以下のいずれかの条件を満たす場合、画面を「Dirty（未保存変更あり）」と判定します。
     - タイトル入力欄に 1 文字以上の入力がある（トリム後空文字以外）。
     - 問い合わせ本文入力欄に 1 文字以上の入力がある（トリム後空文字以外）。
     - 複数所属時において、所属プロジェクトセレクターが未選択から選択状態に変更された。
     - 担当者セレクターが初期値（未設定）から特定の担当者に変更された。
2. **監視対象の離脱操作**:
   - **SPA 内部ルーティング遷移**:
     - サイドバーの他画面リンク（📊 ダッシュボード、📋 問い合わせ一覧）のクリック
     - パンくずリストリンク（ホーム、問い合わせ一覧）のクリック
     - ヘッダーのログアウトボタンのクリック
     - フォームの「キャンセル」ボタンのクリック
     - ブラウザの「戻る」「進む」ボタン操作（TR-18）
   - **ブラウザ外部遷移・リロード**:
     - ブラウザのページリロード（F5 / Ctrl+R）
     - ブラウザタブまたはウィンドウを閉じる操作
     - ブラウザのアドレスバーへの直接 URL 入力による外部移動
3. **離脱確認時の振る舞い**:
   - **SPA 内部遷移時**:
     - Next.js App Router のクライアントサイド遷移をインターセプトし、遷移処理を一時中断して 2.4 項に定義したカスタムモーダルダイアログ（`⚠️ 未保存の変更があります`）を表示します。
     - 利用者が「**留まる**」を選択した場合: ダイアログを閉じ、画面遷移を中止します。入力内容はすべて維持され、フォーカスが直前の入力欄へ戻ります。
     - 利用者が「**破棄して移動**」を選択した場合: Dirty State を解除し、要求されていた遷移先へ移動します。
   - **ブラウザ外部遷移・リロード時**:
     - ブラウザ標準の `beforeunload` イベントダイアログ（「このサイトを離れますか？行った変更が保存されない可能性があります」等）を表示し、誤操作によるデータ消失を防止します。
4. **正常完了時の自動解除**:
   - 「起票する」ボタンを押下し、API による登録が正常に完了した時点（HTTP 201 返却時）で、直ちに Dirty State を解除（`isDirty = false`）します。
   - そのため、後続の SCR-02 問い合わせ詳細画面への自動遷移（TR-14: `/tickets/[id]`）においては、離脱警告ダイアログは表示されずスムーズに遷移します。

## 10. 確認事項・未確定事項

1. **複数プロジェクト所属時の初期選択方針**:
   - 一般ユーザーが複数のプロジェクトに所属している場合、先頭プロジェクトをデフォルトで自動選択状態とするか、あるいはプレースホルダー（`プロジェクトを選択してください`）による明示的な選択を強制するか。
   - **ED での確定方針**: 誤ったプロジェクトへの意図しない起票ミスを防止するため、複数所属時は「プレースホルダー（未選択）」を初期状態とし、利用者に明示選択を求める仕様とする（未選択のまま送信した場合はバリデーションエラー）。単一プロジェクト所属時のみ自動固定とする。
2. **起票完了後の遷移先画面の選定**:
   - 要件定義書では「詳細画面（SCR-02）または一覧画面へ自動遷移」と記載。
   - **ED での確定方針**: 起票直後に内容の確認や追加のコメント記載、ステータス確認を行える利便性を重視し、**新規作成されたチケットの SCR-02 問い合わせ詳細画面（`/tickets/[id]`）への自動遷移を既定仕様** とする（TR-14）。
3. **Next.js App Router 環境下での Dirty State ガードの実装設計（内部設計 ID にて確定）**:
   - Next.js App Router 構成における画面離脱防止は、ブラウザ外部遷移・リロードに対するブラウザ標準の `beforeunload` イベントリスナーと、SPA 内部のクライアント遷移に対するカスタムフック／リンククリックおよびブラウザ履歴操作（戻る・進む）のインターセプト機構を組み合わせて実現します。具体的な実装方式（フック設計・コンテキスト管理等）は、内部設計（ID: `docs/id/01-frontend-architecture.md` 等）にて具体化・確定します。
