## 運用ルールと分類凡例

### 記録必須6項目

| 項目名                   | 説明                                                                                                                           |
| :----------------------- | :----------------------------------------------------------------------------------------------------------------------------- |
| **No.**                  | 当該タスク内での連番（1, 2, ...）                                                                                              |
| **検出手段**             | 不備が最初に確認された手段（例: `手動ブラウザ受入`, `Lighthouse CLI`, `バンドルサイズ分析`, `AIレビュー`, `静的検査` 等）      |
| **成果物区分**           | `製品コード` または `テスト・モック等支援成果物`（仕様書、スクリプト、エビデンス等）                                           |
| **対象箇所**             | 不備が存在したファイル名・関数名・モジュール名・仕様書節名                                                                     |
| **原因分類**             | 原因分類コード（L / S / D / B / A）                                                                                            |
| **不備の概要と是正内容** | 不備の具体的な現象・根本原因、およびどのように是正したか（コミットリンク・PRリンクを含む）を簡潔に記述する（マークダウン形式） |

### 原因分類コード（5分類）

- **L (Logic)**: ロジック誤り（条件分岐ミス、ループ誤り、真偽値反転、フィルタリング・ソート計算ミス）
- **S (State)**: 状態遷移誤り（React state 更新漏れ、Context 値の不整合、ブラウザ履歴・URL クエリ同期ミス、ライフサイクル）
- **D (Design)**: 設計・仕様誤認（OpenAPI 契約や ED/ID 設計書の見落とし、パス・パラメータ・型不一致、認可権限誤認、シードデータ不整合）
- **B (Boundary)**: 境界値未考慮（`null` / `undefined` の考慮漏れ、空文字・空配列、最大文字数超過、極端な解像度での崩れ）
- **A (Async)**: 非同期制御不備（Promise ハンドリング漏れ、Service Worker 初期化競合、Race Condition、遅延レスポンス上書き）

### 成果物区分の定義

- **製品コード**:
  `src/` 配下のプロダクションコード（画面、フック、コンポーネント、ルーター、API クライアント等）に存在した不備。
  先行工程の品質および最終リリース判定を測る「総合欠陥除去率（$\text{DRE (Total)}$）」の算定対象（分子・分母）となります。
- **テスト・モック等支援成果物**:
  PT 計画書・受入仕様書（`docs/pt/`）、結合テストコード（`test/it/`）、単体テストコード（`*.test.tsx`）、MSW ハンドラー・データストア（`src/mocks/`）、測定スクリプト、Storybook、設定等の不備。
  製品コードのバグ密度や真の DRE を歪めないよう別集計とし、製品コード欠陥数には含めません。
