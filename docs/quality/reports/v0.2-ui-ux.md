# Milestone `v0.2`（UI/UX・操作性刷新 ＆ 開発基盤整備）品質分析・振り返りレポート（Kaizen）

## 1. エグゼクティブサマリー（Executive Summary）

Milestone `v0.2`（UI/UX・操作性刷新 ＆ 開発基盤整備）では、Milestone `v0.1` で完成した 3 画面基本機能およびアプリアイコン設定を基盤として、以下の 4 つの機能要望・基盤改善 Issue（#49〜#52）を Issue 駆動マイクロウォーターフォール（① Open Questions 解消 → ② 設計更新 PR → ③ 製造（MK）Sub-issue PR → ④ 結合テスト（IT）PR）に沿って完遂した。

1. **Issue #49（`generate-icons.test.ts` のモック化・CI分離による lint-and-unit ジョブの完全ブラウザレス化 `HO-10`）**：`chromium.launch()` のモック化により、単体テスト・静的解析ジョブから実ブラウザ起動と OS パッケージ依存を完全排除し、CI 所要時間を大幅に短縮。
2. **Issue #50（100dvh 全画面シェル・下部タブバー・設定画面 `SCR-05` 新設・OS バックキー論理階層遷移）**：`src/App.tsx` の 100dvh 固定化、画面下部共通ナビゲーション `BottomTabBar`（「本棚」「設定」）、組版 4 設定（縦横切替・4カラーテーマ・文字サイズ・行間）をリアルタイム反映する設定画面 `SCR-05`（`/settings`）および `SampleTextPreview`、ならびに論理階層順（各話View → 目次 → 本棚、設定 → 直前画面 `TR-12`）での OS バックキー復帰制御を実装。
3. **Issue #51（作品詳細・目次画面 `SCR-02` のヘッダー固定・あらすじトグル化・各話内部スクロール ＆ しおり初期スクロール調整）**：`NovelDetailHeader` の上部固定・あらすじ展開トグル化（`synopsis-toggle-button`）、各話リストの独立内部スクロール化（`flex-1 min-h-0 overflow-y-auto`）、読書中作品のしおり話数への初期スクロール位置自動復元、および「目次を更新」時のスクロール維持を実装。
4. **Issue #52（小説リーダー画面 `SCR-03` の全画面テキスト表示化・下部オーバーレイ導入）**：常時表示型ツールバーを廃止してリーダー画面を全画面テキスト表示化、画面最下部タッチ（72px / 15% 領域）によるスライドイン下部オーバーレイ（`ReaderBottomOverlay`：前後話ナビ ＋ 下部タブ）、および画面離脱時のしおり・スクロール進捗率即時保存（`flushBookmark`）を実装。

全要望 PR マージ後、**Issue #53（Milestone `v0.2` 全体横断レビュー・品質分析・完了承認）** において、マルチモデル 3 オーケストレーター（`Gemini 3.8 Flash` / `Gemini Pro` / `Copilot SDK`）による網羅的な節目横断レビュー（Round 1）を実施した。検出された **全 21 件の指摘事項（`R1-01`〜`R1-21`：`[P2]` 18 件 / `[P3]` 3 件）** に対し、製品コード修正・単体テスト拡充・Storybook / VRT 更新・実ブラウザ IT アサーション拡張・OKF 仕様書同期・ガイドライン/スキル改善を直列に実施してすべて解消した。

### 3.2 傾向分析と考察

1. **原因 `D`（Design）の依然として高い比率（65.5%）**:
   - 仕様書間の双方向トレーサビリティ（要件 ID ⇄ 受入条件 ID、親正本 ⇄ 差分仕様）の記述漏れや、機能変更に伴う旧仕様（ツールバーボタン等）の正本残存が主因である。
   - 一方で、本リポジトリのルール「原因 `D` はコードのみならず必ず仕様書（`docs/specs/`）を同一 PR で即時同期する」が徹底され、29 件すべてにおいて設計書と実装の 1 対 1 対応が回復された。
2. **原因 `A`（運用・衛生・記録）の増加（24.1%）**:
   - 孤児 VRT スナップショット（削除された Story の画像ファイル）の残存や、バグ記録票におけるコミット SHA の記載漏れなど、アセット衛生や記録規律に関する不備が目立った。
   - これに対し、孤児スナップショット検知ガードテスト（`vrt.spec.ts`）を機械化するなど、人手や AI の記憶に頼らない決定論的セーフガードを構築した。
3. **ロジックバグ（原因 `L`）の激減（3.4%）**:
   - Phase 3（35.5%）→ Milestone `v0.1`（38.5%）から、Milestone `v0.2` では 3.4%（1件）へと激減した。
   - 100% カバレッジ（C0/C1/Functions）を維持する TDD Red-Green-Refactor サイクルと、Playwright 実ブラウザ IT による全画面階層検証が定着した成果である。

## 4. プロセス・スキル改善（Kaizen アクション）

Milestone `v0.2` の横断レビューおよび品質分析から得られた教訓に基づき、以下の 3 つのプロセス・スキル改善を実施した。

### 4.1 VRT 孤児スナップショット検知ガードの自動化（`R1-12` 再発防止）

- **課題**: Storybook のストーリーを削除・改名した際、`playwright test --update-snapshots` は旧 PNG ファイルを削除しないため、不要な画像アセットがリポジトリに残存していた。
- **改善アクション**: `test/vrt/vrt.spec.ts` にガードテストを追加し、`storybook-static/index.json` に存在する対象ストーリー一覧と `test/vrt/snapshots/` 内の PNG ファイル一覧が 1 対 1 で完全一致すること（孤児スナップショット 0 件）を機械検証するようにした。
- **反映先**: `test/vrt/vrt.spec.ts`, `docs/guidelines/testing.md` §2.3, `.github/skills/c-ut-workflow/SKILL.md` Step 4。

### 4.2 非同期永続化におけるエラー通知・ロールバック規律（`R1-20` 再発防止）

- **課題**: 設定変更等の非同期保存処理において、更新失敗時にエラーが画面へ伝搬されず、未保存の値が画面上に有効であるかのように見えていた。
- **改善アクション**: 非同期永続化を伴う UI/Container では、保存失敗時に直前の state へロールバックし、画面上部（ヘッダー直下）に `role="alert"`（`data-testid="*-error-alert"`）でユーザーへエラーを明示する設計規律を義務化した。
- **反映先**: `docs/specs/features/settings.md` §3.2, §4.2, §5, `docs/guidelines/testing.md` §2.3, `.github/skills/c-ut-workflow/SKILL.md` Step 1。

### 4.3 ルーティング同一パスガード規律（`R1-21` 再発防止）

- **課題**: 下部タブバー等のナビゲーション操作において、既に表示中の同一ルートを再タップした際に `history.pushState` が重複実行され、OS バックキーの直前画面復帰（`TR-12`）履歴が破壊されていた。
- **改善アクション**: `router.tsx` において同一パスへの遷移要求を no-op とするガードを導入し、重複履歴の追加を抑止した。あわせて実ブラウザ IT（`scn01-poc-vertical-reader.spec.ts`）において、設定画面での同一タブ再タップ後も 1 回の戻る操作で直前画面へ復帰できることを検証した。
- **反映先**: `src/app/router.tsx`, `docs/specs/screen-transitions.md`, `docs/guidelines/testing.md` §2.3, `.github/skills/c-ut-workflow/SKILL.md` Step 1。

## 5. 次期マイルストーン（Milestone `v0.3`）へ向けた申し送り事項

Milestone `v0.2` で起票された申し送り事項（`HO-10`〜`HO-13`）はすべて解決（`Resolved`）済みとなり、未解決の `HO` アイテムは 0 件である。

Milestone `v0.3`（マルチサイト対応 ＆ DLキュー制御：なろう対応、一括取得キュー、レートリミット制御、新着更新チェック、フォント種別・余白設定、タップ/音量キー送り）に向けて、以下の品質指針を引き継ぐ：

1. **外部小説サイトパーサー追加時の事前調査徹底**: 『小説家になろう』パーサー（`NarouParser`）策定にあたり、HTML 構造・ルビ `<ruby>` 形式・挿絵タグ・埋め込みスクリプトの事前調査を行い、多彩な作品フィクスチャを用意すること。
2. **バックグラウンドキューのレートリミット（1.5秒待機）と非同期キャンセル検証**: 503 IP BAN を防ぐウェイト制御、`AbortController` 連携、アプリ終了時の再開（SQLite 永続化）の単体・結合テストを Red-Green 規律で徹底すること。
3. **100dvh 全画面シェルおよび `BottomTabBar` との調和**: 新設される DL キュー画面や設定拡張（フォント・余白・ページ送り）を既存の全画面シェルおよび論理階層遷移（OS バックキー）と完全に調和させること。
