> [!IMPORTANT] 設計時の注意点
> - **全データ削除**は破壊的な操作であるため、誤操作防止策（警告ダイアログ）と安全な実行手順（トランザクション、バックグラウンド処理停止）を徹底すること。
> - 設定値は `DataStore (Preferences)` を使用して永続化し、ビューアー設定（FD-006）と共通のインスタンスまたはキー管理を行う。

---

## 1. 概要
ユーザーがアプリの動作やデータ管理設定を行うための画面。先読み機能の調整、キャッシュ削除、全データの初期化等を提供する。

> [!NOTE] 提供価値
> - ユーザーの通信環境やストレージ状況に応じたカスタマイズを可能にする。
> - アプリの動作が重くなった際や、初期化したい場合のメンテナンス機能を提供する。

## 4. イベント・関数詳細

### 4.1. ViewModel: `SettingsViewModel`

| 関数名 | 引数 | 戻り値 | 処理概要 |
| :--- | :--- | :--- | :--- |
| `updatePrefetchCount` | `count: PrefetchCount` | `Unit` | 先読み話数設定を更新する。 |
71: | `updateThemeMode` | `mode: ThemeMode` | `Unit` | テーマ設定を更新する。 |
72: | `deleteCache` | なし | `Unit` | 全作品のキャッシュ（本文データ）を削除する。 |
73: | `deleteAllData` | なし | `Unit` | アプリの全データを初期化する。 |

#### 詳細ロジック

**`updatePrefetchCount(count)`**
1. `userPreferencesRepository.savePrefetchCount(count)` を呼び出す。
2. **WorkManager連携**:
    - `count == PrefetchCount.NONE (0)` の場合:
        - `workManager.cancelAllWorkByTag("prefetch_worker")` を呼び出し、バックグラウンド更新を即時停止する。
    - `count > 0` の場合:
        - 既存のWorkが稼働中の場合、次回の実行時に新しい設定値（DataStore）を参照するため、特別な再スケジュールは不要（または必要に応じて `enqueueUniqueWork` で置き換える）。

**`deleteCache()`**
1. `_uiState.update { it.copy(isDeleting = true) }`
2. `viewModelScope.launch(Dispatchers.IO)` で実行。
3. `novelRepository.clearAllEpisodeContent()` を呼び出す。
   - SQL: `UPDATE Episodes SET content_html = NULL, last_fetched_at = NULL`
4. 完了後、トースト通知「キャッシュを削除しました」を表示し、`isDeleting = false` に戻す。

**`deleteAllData()`**
1. **事前処理**: `WorkManager.cancelAllWork()` を呼び出し、バックグラウンド更新を停止。
2. `_uiState.update { it.copy(isDeleting = true) }`
3. `viewModelScope.launch(Dispatchers.IO)` で実行。
4. `novelRepository.deleteAllData()` を呼び出す（トランザクション実行）。
   - `DELETE FROM NovelTags`
   - `DELETE FROM SearchCache`
   - `DELETE FROM Episodes`
   - `DELETE FROM Novels`
   - `DataStore` の設定値も初期化（必要であれば）
5. 完了後、`isDeleting = false` にし、ナビゲーションイベントを発火して「検索画面」へ遷移させる。

## 5. データベース・API アクセス

### データベース (Room)

#### `EpisodeDao`
- `clearAllContent()`: 本文キャッシュの一括削除。

#### `AppDatabase` (Transaction)
- `deleteAllTables()`: 全テーブルのデータを削除するメソッド。`@Transaction` アノテーションを使用。

### DataStore (Preferences)

- キー定義 (`PermissionKeys` / `SettingKeys`)
  - `KEY_APP_PREFETCH_COUNT` (Int): 先読みエピソード数。
  - `KEY_APP_THEME_MODE` (String): アプリ全体のテーマ設定（FD-006の `viewer_theme_mode` とは別）。

## 6. エラーハンドリング・境界値

| ケース | 挙動 | ユーザーへのフィードバック |
| :--- | :--- | :--- |
| **削除中のアプリ終了** | トランザクションによりロールバックされるか、中途半端な状態を防ぐ（Roomの仕様に依存）。再起動時は不整合がない状態を保つ。 | 特になし（次回起動時に正常動作）。 |
| **WorkManager停止失敗** | ログ出力し、削除処理は続行（DB削除が優先）。 | ユーザーへは通知しない。 |

> [!TIP] 実装のポイント
> - **全データ削除後の遷移**: データが空になるため、本棚画面ではなく「検索画面」へ誘導することで、ユーザーの次のアクション（作品探し）を促す。
> - **ライセンス画面遷移**: `SettingsScreen` からのナビゲーションイベントとして処理する。
