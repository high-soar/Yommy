# Review Viewpoints for Devil's Advocate

このドキュメントはレビュー時の観点と判断基準を定義する。
リスクがインシデントになる前に特定することが目的である。

SKILL.md の3カテゴリに対応させ、各カテゴリ内にサブ観点を配置する。

---

## 1. Fatal Defect (致命的な欠陥)

*システムの存続、安全性、データ保全を脅かす問題。*

### セキュリティ・プライバシー

- WebViewにおけるXSS・JavaScriptインジェクションのリスクはないか？
- 外部サイトからの取得データ（HTML）を無害化（サニタイズ）せずに表示していないか？
- ログやクラッシュレポートにユーザーの閲覧履歴・個人情報が漏洩していないか？
- シークレット（APIキー等）がハードコードされていないか？

### パフォーマンス・リソース管理

- ネットワークリクエストがUIスレッドをブロックしていないか？
- リソースリーク（メモリ、DB接続、ファイルハンドル）の可能性はないか？
- 低スペック端末（Fire HD）で大量データ（数百作品、数千エピソード）処理時にOOMに陥らないか？
- バックグラウンド処理（WorkManager）がバッテリーを過剰消費しないか？

### データ整合性

- DBの書き込み操作は冪等か？（ネットワーク遅延で同じ操作が2回実行されたらどうなるか）
- 並行処理によるレースコンディション（例: バックグラウンド更新とユーザー操作の競合）のリスクはないか？
- Room DBのマイグレーション戦略は定義されているか？（スキーマ変更時にデータが消失しないか）

### 外部依存の脆弱性

- 対象サイトのDOM構造変更に対する耐性はあるか？フォールバックは定義されているか？
- スクレイピング対象のアクセス制限（リクエスト間隔、User-Agent）は守られているか？
- 外部サイトが応答しない場合のタイムアウト・リトライ戦略は定義されているか？

## 2. Logical Contradiction (論理的矛盾)

*ロジック内部の矛盾、仕様間の不整合、現実との乖離。*

### 仕様間の整合性

- 実装は要求仕様を正確に反映しているか？開発者が都合よく「解釈」していないか？
- 画面設計のデータ表示項目と、DB設計のカラムに過不足がないか？
- 異なるドキュメント間で同一の概念に対して矛盾する定義がないか？

### 状態遷移の妥当性

- 状態遷移は論理的に有効か？到達不能な状態や無限ループはないか？
  - 例: 読書位置の保存・復帰ロジック、未読/既読状態の管理
- エラー状態からの復帰パスは定義されているか？

### 時間的ロジック

- タイムアウトとリトライの上限は定義されているか？（無限待機によるシステムハング）
- ネットワーク遅延を考慮しても処理の順序は論理的に成立するか？
- キャッシュの有効期限・更新タイミングは矛盾なく定義されているか？

### ユーザー操作との矛盾

- ユーザーの操作パターン（画面回転、バックキー、マルチタスク切替）でアプリが破綻しないか？
- オフライン時のUXフローは一貫しているか？エラー表示だけでなく代替手段が提示されるか？

## 3. Lack of Concreteness (具体性の欠如)

*曖昧で実装者の裁量に委ねざるを得ない定義。テスト不能な仕様。*

### 定量的基準の欠如

- 「負荷を考慮」「過度なアクセスを抑制」等の表現に具体的な数値（リクエスト間隔、上限数）が定義されているか？
- パフォーマンス要件（画面表示までの許容時間、キャッシュサイズ上限等）は定量化されているか？

### エッジケースの未定義

- Null / 空 / 未定義入力時の挙動は定義されているか？
- 最大値・最小値（作品数上限、エピソード数上限、タイトル文字数上限）は定義されているか？
- 異常入力（絵文字を含むテキスト、巨大なHTML）への対策はあるか？

### テスト容易性

- ロジックはユニットテスト可能な粒度で分離されているか？
- 非決定的な挙動（現在時刻、ネットワーク状態）がテストを不安定にしないか？
- 外部サイトに依存せずテストできる設計か？（テストデータ・モックの方針）

### エラーハンドリングの具体性

- エラー発生時のユーザーへの通知方法（メッセージ内容、表示位置、操作の可否）は具体化されているか？
- リトライ戦略（回数、間隔、バックオフ）は定義されているか？
- 例外が握りつぶされていないか？（try-catch で空ブロック）

### 運用・保守の具体性

- ログは障害調査に十分なコンテキスト（エラー箇所、入力パラメータ、スタックトレース）を含んでいるか？
- モジュール間の依存関係は明確か？循環依存や God Class は存在しないか？
- 設定値はコードから分離されているか？（マジックナンバーの有無）
