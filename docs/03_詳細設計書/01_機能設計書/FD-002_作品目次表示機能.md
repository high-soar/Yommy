## 1. 概要
選択された小説の詳細情報と、エピソード一覧（目次）を表示する。
ユーザーはここから各エピソードの閲覧を開始したり、続きから読んだり、手動で更新チェックを行うことができる。

> [!NOTE] 主要機能
> - 作品詳細情報（タイトル、作者、あらすじ、タグなど）の表示。
> - エピソードリストの表示（未読/既読状態、キャッシュ有無）。
> - **レジューム機能**: 「続きから読む」ボタンで前回中断箇所へ遷移。
> - **単体更新**: この作品のみの最新話取得。

## 3. UI状態 (UI State)

### 定義 (`NovelDetailUiState`)

```kotlin
data class NovelDetailUiState(
    val isLoading: Boolean = true,
    val novel: Novel? = null,
    val episodes: List<Episode> = emptyList(),
    val errorMessage: String? = null,
    val isUpdating: Boolean = false // 更新ボタン連動
)
```

> - **novel**: 表示対象の作品データ。nullの場合はロード中かエラー。
> - **episodes**: 該当作品のエピソードリスト。`index_order` 昇順。
> - **isUpdating**: 手動更新実行中のインジケータ制御。

## 4. イベント・関数詳細

### 4.1. ViewModel: `NovelDetailViewModel`

| 関数名 | 引数 | 戻り値 | 処理概要 |
| :--- | :--- | :--- | :--- |
| `loadData` | `novelId: String` | `Unit` | 指定IDの作品情報とエピソード一覧をDBから取得し監視する。 |
| `manualUpdate` | `novelId: String` | `Unit` | この作品の最新データをサイトから取得する（FD-003呼び出し）。 |
| `resumeReading` | なし | `Event` | 「続きから読む」アクション。遷移先情報（episodeId, position）をViewに通知。 |
| `deleteNovel` | なし | `Unit` | 表示中の作品を削除し、前画面へ戻る（FD-004呼び出し）。 |

#### 詳細ロジック

**`loadData(novelId)`**
1. `_uiState.update { it.copy(isLoading = true) }`
2. `viewModelScope.launch` で実行。
3. `novelRepository.getNovelFlow(novelId)` と `novelRepository.getEpisodesFlow(novelId)` を `combine` して監視。
    - 作品情報またはエピソードリストの変更を即座に反映させるため。
4. 結合されたデータを `uiState` に反映:
    ```kotlin
    combine(novelFlow, episodesFlow) { novel, episodes ->
        NovelDetailUiState(
            isLoading = false,
            novel = novel,
            episodes = episodes
        )
    }.collect { _uiState.value = it }
    ```
5. データが存在しない（削除された等）場合、エラーまたは画面終了処理を行う。

**`resumeReading()`**
1. `uiState.value.novel` から `last_read_episode_id` を取得。
2. 未読の場合（`last_read_episode_id` が null または 0）、最初のエピソードIDを取得。
3. Viewに対して `NavigateToViewer(episodeId, position)` イベントを発行。
    - `position` は `novel.last_read_position` を使用。

**`manualUpdate(novelId)`**
1. `_uiState.update { it.copy(isUpdating = true) }`
2. `repository.updateNovel(novelId)` を実行（非同期）。
3. 成功・失敗に関わらず `isUpdating = false` に戻す（エラー時はメッセージ表示）。
4. 成功すればDBが更新され、Flow経由で自動的にリストが増える。

## 5. データベース・API アクセス

### データベース (Room DAO)

- **`NovelDao.getNovelFlow(id): Flow<Novel?>`**
- **`EpisodeDao.getEpisodesFlow(novelId): Flow<List<Episode>>`**
  - ソート順: `index_order ASC`
- **`EpisodeDao.getEpisode(id)`**
  - レジューム時のエピソード存在確認用。

### API

- 更新ボタン押下時に `KakuyomuApiService` を使用するが、これは `NovelRepository` 内部または `WorkManager` (FD-003) に隠蔽される。

## 6. エラーハンドリング・境界値

| ケース | 挙動 | ユーザーへのフィードバック |
| :--- | :--- | :--- |
| **ID不一致 (404)** | 画面を閉じる、またはエラー表示。 | **ローカルDBにデータが存在しない**場合。「作品が見つかりません」と表示し、自動的に本棚へ戻る。 |
| **エピソード0件** | 目次リストを空表示。「更新」を促す。 | 「エピソードが取得できていません。更新ボタンを押してください」と表示。 |
| **更新失敗** | リスト維持。 | スナックバーで「更新に失敗しました」と表示。 |

## 7. 補足 (UI/UX)

- **スクロール連動**: エピソード数が多い場合、ヘッダー（作品情報）を折りたたんでリストを広く使う（Collapsing Toolbar）。
- **未読強調**: 未読エピソードの左端にアクセントカラーのバーを表示、または太字にするなどして視認性を高める。
- **キャッシュ表示**: ダウンロード済みのエピソードには「保存済み」アイコン（チェックマークやスマホアイコンなど）を表示する。`content_html` がnullでない判定（1MB超過でNULLの場合は保存済みとみなされないため、手動取得時にサイズ超過エラーを表示する等の対応が必要）。
