# Milestone `v0.8`（探索フィルタ高度化 ＆ 本棚お気に入り管理）品質分析・振り返りレポート（Kaizen）

## 1. エグゼクティブサマリー（Executive Summary）

Milestone `v0.8`（Discovery Filter Enhancement & Bookshelf Favorite Management）では、マルチサイト（カクヨム・小説家になろう）の小説探索体験を飛躍的に高める **「高度検索フィルタ（除外キーワード・複数ジャンル選択）」** および **「作品種別（長編/連載・短編）フィルタ切替」**、ならびに長編読書の蔵書管理を快適化する **「作品のお気に入り（★）登録・本棚フィルタ・Google Drive クラウド同期連携」** の 3 つの親 Issue（`#264`, `#265`, `#266`）を完遂した。

1. **Issue #264（検索画面［SCR-06］の高度検索フィルタ機能：除外キーワード・複数ジャンル選択、HO-31）**:
   - `SearchInputBar` に折りたたみ式の除外キーワード入力パネル（`excludeQuery`、未展開時の設定ドットインジケーター付き）を新設し、カクヨム（`-語` 結合）および小説家になろう（`notword` パラメータ）双方の除外検索に対応（`AC-SE-10`）。
   - `GenrePillSelector` を複数ジャンル選択（`genres?: string[]`）へ拡張し、「すべて」ピルによる一括解除やサイト切替時の選択状態リセットを実装（`AC-SE-04` 改訂）。
2. **Issue #265（ランキング・検索画面［SCR-07 / SCR-06］における作品種別［長編/連載・短編］フィルタ切替対応）**:
   - ランキング画面の `RankingFilterBar` に作品種別ピル（`すべて` / `長編` / `短編`、カクヨム初期値 `long`・なろう初期値 `all`）を追加し、カクヨム（`work_variation`）となろう（`type=r/er/t`）の種別別ランキング取得に対応（`AC-RK-10`）。
   - 検索画面の連載状態フィルタ（`SearchSerialStatus`）に `short`（短編）を追加し、なろう（`type=t/r/er`）およびカクヨム（`serial_status=completed` ＋ `total_character_count_range=-20000` の完結・20,000文字以下複合条件）での短編検索を実現（`AC-SE-05` 改訂）。
3. **Issue #266（作品のお気に入り［★］登録・クラウド同期連携と本棚お気に入りフィルタ機能、HO-32）**:
   - SQLite `novels` テーブルへの `is_favorite` カラム追加（既存 DB 自動マイグレーション対応）および `reader_settings.bookshelf_favorite_only` によるフィルタ状態の永続化を実装（`AC-BS-15`〜`19`, `AC-ND-13`）。
   - 本棚のお気に入りフィルタ ON 時は、自動/手動の更新チェック対象もお気に入り作品のみに絞り込む通信最適化を実現（`AC-BS-18`）。
   - Google Drive クラウド同期ペイロード（`SyncedNovelItem`）に `isFavorite` を追加し、`novels.updated_at` による LWW（Last-Write-Wins）競合調停と定常処理での `updated_at` 非汚染保護規約を確立（`AC-CS-03`〜`05` 改訂）。

全機能 PR マージ後、**Issue #267（Milestone `v0.8` 全体横断レビュー・品質分析・完了承認）** において、マルチモデル 3 オーケストレーターによる独立横断レビュー **Round 1（`R1-01`〜`R1-23`：Sub-issue `#288` / PR `#289`）** および **Round 2（`R2-01`〜`R2-17`）＋ Android 実機検証（`HO-31`〜`HO-33` / `R2-18`〜`R2-20`：Sub-issue `#290` / PR `#291`）** を実施した。
全 46 件の指摘・実機検出事項（LWW タイムスタンプ保護 `R1-01`・初回 Pull 時 `createdAt`/`updatedAt` 完全復元 `R2-02`、カクヨム短編検索の 20,000 文字以下条件付与 `R2-18`、お気に入りトグル時の常時 1px `border` 維持による 2px 高さちらつき解消 `R2-19`、375px 狭幅本棚ヘッダーの `★`/`☆` アイコン省スペース化 `R2-20`、決定論的 LWW/URL E2E 検証 `R1-03`/`R2-05`/`R2-11` 等）を自律マージにて完全収束させ、全自動テスト（UT 1,807 件 / カバレッジ 100%、VRT 478 件、IT 17 件）の PASS を達成した。

## 5. Milestone `v0.8` 固有の設計的知見と再発防止策（Kaizen アクション）

Milestone `v0.8` 横断レビュー（Round 1: `R1-01`〜`R1-23`、Round 2: `R2-01`〜`R2-17`）および Android 実機検証（`R2-18`〜`R2-20`）から得られた教訓に基づき、`docs/guidelines/testing.md` および `.github/skills/c-ut-workflow/SKILL.md` に以下の 4 つの再発防止規律を恒久反映した。

### 5.1 クラウド同期 LWW（`novels.updated_at` / `created_at`）の定常処理非汚染と初回 Pull 時タイムスタンプ完全復元・決定論的 IT 検証（`R1-01`, `R1-19`, `R2-02`, `R2-05`, `R2-16` 再発防止）

- **課題**:
  1. `novels.updated_at` はクラウド同期において作品単位メタデータ（`isFavorite` 等）の LWW（Last-Write-Wins）勝敗判定に使用されるが、目次更新チェック（`upsertNovelWithToc` の既存作品更新）、しおり更新（`updateBookmark`）、本文キャッシュ保存・再集計（`saveChapterBody`, `recalculateNovelStats`）、および一括キャッシュ中のローカル State 更新（`startBatchCache`）で `updated_at` が現在時刻へ書き換わっていたため、読書や更新チェックを行うだけで古い `isFavorite` 状態が他端末の最新変更を上書き消失させる不備があった（`R1-01`, `R2-16`）。
  2. 新規作品を Pull 取り込み（`mergeNewNovel`）する際、`updateSyncMetadata` で `remoteNovel.updatedAt` のみを復元し `remoteNovel.createdAt` を復元していなかったため、`created_at` が Pull 実行時のローカル現在時刻となり、他端末の未 Push Tombstone（`deletedAt < localCreatedAt`）が「削除後の再登録」と誤判定されて削除済み作品が復活する不備があった（`R1-19`, `R2-02`）。
  3. `SCN-05` の LWW 結合テストでリモート側の `updatedAt` に未来時刻（`Date.now() + 10_000`）を設定していたため、定常処理でローカル `updated_at` が現在時刻に汚染されてもリモート側が勝ってしまい、`R1-01` の回帰を検出できないテスト構造となっていた（`R2-05`）。
- **対策**:
  - `novels.updated_at` を更新してよい操作は「新規作品登録時」および「ユーザーが明示的に作品単位の同期対象属性（`setFavorite` 等）を変更した時」のみに厳格限定し、定常的な目次更新・しおり更新・本文キャッシュ保存/削除/再集計・ローカル進捗 State 更新では `updated_at` を一切変更しない。
  - `mergeNewNovel` による新規作品 Pull 復元時は、`updateSyncMetadata` に `createdAt: remoteNovel.createdAt` と `updatedAt: remoteNovel.updatedAt` の双方を渡してリモートタイムスタンプを完全復元する。
  - 結合テスト（IT）で LWW 保護を検証する際は、未来時刻（`+10秒`）の使用を禁止し、必ず過去のタイムライン `T1（ローカル初期） < T2（リモートお気に入り変更） < now（定常処理実行時刻）` を構築した上で、現在時刻 `now` にしおり更新等の定常処理を実行してから同期し、時刻 `T2` のリモート変更が勝利することを決定論的に検証する。

### 5.2 外部サイト検索パラメータ（プリセット複合条件）の実サイト仕様調査と `committedQueryRef`・E2E URL `expect.poll` 検証（`R1-03`, `R1-07`, `R2-11`, `R2-18` 再発防止）

- **課題**:
  1. カクヨム Web 検索の「短編」絞り込みにおいて、カクヨム実サイトの UI プリセットは `serial_status=completed`（完結済）単体ではなく `total_character_count_range=-20000`（20,000文字以下）との複合クエリに変換される仕様であったが、初期実装では `serial_status=completed` のみを送信していたため、実機検索で数百万文字の長編完結作品が大量に混入した（`R2-18`）。
  2. 検索実行後にキーワード入力欄やフィルタを変更した状態で（検索ボタンを押さずに）`loadMore`（次ページ取得）を実行すると、未確定の入力中 state で次ページが取得されてしまう不備があった（`R1-07`）。
  3. 結合テスト `SCN-02` において、初期実装ではフィルタ操作後のカード表示のみを確認し、実際に HTTP クライアントへ渡された URL クエリパラメータを検証していなかった（`R1-03`, `R2-11`）。
- **対策**:
  - 外部サイトの検索・ランキングフィルタを実装する際は、実サイトのフォーム送信 URL やプリセット選択時の複合クエリパラメータ（文字数範囲・除外語・種別コード等）を事前調査して `docs/specs/parsers/*.md` に明記し、単体テストと結合テスト（`expect.poll` による送信 URL クエリ捕捉）の双方で全種別パラメータを厳密にアサートする。
  - ページネーション（`loadMore`）を持つ検索 Hook では、検索実行時点の確定条件スナップショット（`committedQueryRef`）を保持し、次ページ取得時は入力中の未確定 state ではなく `committedQueryRef.current` を使用する。

### 5.3 モバイル狭幅（375px）ヘッダーの省スペース化・トグルボタン常時 1px `border` 維持による 2px 高さちらつき防止・排他ガード・条件付き `aria-controls`（`R1-09`, `R1-10`, `R2-01`, `R2-08`, `R2-09`, `R2-19`, `R2-20` 再発防止）

- **課題**:
  1. 作品詳細ヘッダーのお気に入りボタンで、OFF 時（`☆ お気に入り`、枠線なし）と ON 時（`★ お気に入り済み`、`border` 1px あり・2文字増）で文字数と枠線有無が変化していたため、実機タップ時にボタン高さが 2px・横幅が 2 文字分伸縮してレイアウトシフト（ちらつき）が発生した（`R2-19`）。
  2. 本棚ヘッダーのお気に入りフィルタボタンに `★ お気に入り` とテキストを表示していたため、360px〜375px のモバイル狭幅実機で更新チェック進捗（「更新中 (1/5)...」）やソートセレクター・更新ボタンと並んだ際に横幅が溢れて改行崩れを起こした（`R2-20`）。
  3. トグルボタンの連打排他ガード漏れ（`R1-09`, `R2-08`）や、条件付きマウントされる折りたたみパネル（除外キーワード欄）に対する常時 `aria-controls` 出力（未展開時に存在しない DOM ID を参照：`R2-09`）が発生した。
- **対策**:
  - ON/OFF を切り替えるトグルボタンでは、**① 表示ラベルの文字数を固定（「済み」の付け外しを行わず `★`/`☆` と色変化のみで表現）** し、**② ON/OFF 双方で常時 `border`（1px）クラスを維持（色のみ切替）** することで、トグル時の 2px 高さ変化・横幅伸縮によるレイアウトシフトを根絶する。
  - 375px モバイル狭幅ヘッダーで複数の操作コントロールや進捗テキストと共存するフィルタトグルボタンは、アイコンのみ（`★`/`☆`）＋ `shrink-0 whitespace-nowrap` ＋ 固定 `aria-label` ＋ `aria-pressed` で省スペース設計とする。
  - 条件付きレンダリング（`{isOpen && <div id={panelId}>}`）される要素を制御するトグルボタンでは、`useId()` で一意 ID を生成し、**パネル展開時（`isOpen === true`）のみ `aria-controls={panelId}` を出力** する（折りたたみ時は `undefined`）。
  - 非同期 DB 永続化を伴うトグル操作には、作品 ID 単位（`Set<string>` ref）または操作単位（`boolean` ref）の排他ロックガードを必ず設ける。

### 5.4 品質記録台帳（`bug-and-handover-log.md`）のセル内パイプ禁止と原因 `D` 分類・設計同期コミット SHA 厳格化（`R1-11`, `R2-01`, `R2-03`, `R2-07` 再発防止）

- **課題**:
  - Markdown テーブルのセル内インラインコードに TypeScript ユニオン型等のパイプ記号（`` `a | b` ``）を記述した際、GFM パーサーおよび Prettier がセル区切りと解釈してテーブル列が破損する事象が複数回発生した（No. 234, No. 261）。
  - また、横断レビュー是正時に原因分類 `D` の設計同期コミット SHA が「本 PR」のまま残存したり、正本仕様書の変更を伴わないテスト・コメント修正が `D` に分類される不整合があった（No. 246, No. 265）。
- **対策**:
  - Markdown テーブルセル内のインラインコードには未エスケープの `|` を記述せず、`/` 区切りまたは個別のバッククォート表記（`` `"kakuyomu"` / `"narou"` ``）を使用する。
  - バグ記録の原因分類 `D` は `docs/specs/`（正本仕様書または差分仕様書）の仕様誤認・不備・未同期を修正した場合に厳格限定し、是正内容欄には必ず具体的な設計同期コミット SHA を明記する。
