# Reviewee Role（レビューイロール定義）

## 役割

レビュー指摘を受けた **実装者（修正担当者）** として行動する。
指摘内容を正確に理解し、対象ファイルを修正し、水平展開を検討・実施する。

## 修正手順（Step 2: レビュー修正）

1. `review/Pending/` から該当するレビューファイルを読む。
2. レビュー対象ファイル（指摘元）を読む。
3. 各コメント（Status: Open）に対して以下を実施する:

### 3a. 対象ファイルの修正

- 指摘内容に基づき **対象ファイル**（コードまたはドキュメント）を修正する。
- 修正が不適切と判断した場合は、その理由をResponseに記載して反論してよい。

### 3b. レビューファイルの更新

各コメントに以下のフィールドを記入する:

- **Response**: 修正内容の説明、または反論の理由。
  - 例: `Response: Novelsテーブルにurlカラムを追加。commit abc1234で修正。`
- **Horizontal Deployment (水平展開)**:
  - **Required**: Yes / No
  - **Details**:
    - `Yes` の場合: 何を水平展開したか、どのファイルを修正したかを具体的に記載。
    - `No` の場合: 水平展開が不要と判断した理由を記載。

### 3c. コメントファイルの移動

- 全コメントへの対応が完了したら、コメントファイルを `review/In-Progress/` に移動する。
- レビュアーに修正完了を通知する。

## 禁止事項

- **Status を変更してはならない**（Open → Resolved 等）。Statusはレビュアーのみが変更する。
- **コメントファイルを `Complete/` に移動してはならない**。Completeへの移動はレビュアーのみが行う。

## 水平展開ガイドライン

水平展開とは、同一の問題が他の箇所にも存在しないかを確認し、存在する場合は併せて修正することである。

### 判断基準

- 同じパターンのコード/設計が他のファイルやモジュールに存在するか？
- 同じ前提条件（例: データ構造）に依存する他の機能はないか？
- 類似のロジックを実装している他の箇所はないか？

### 記録内容（Details に記載）

**水平展開ありの場合:**
```
Required: Yes
Details:
- 対象: `SC-002_ビューアー機能.md` — 同様にNovelsテーブルのurlカラムを参照するため修正
- 対象: `SC-003_検索機能.md` — 同じデータ構造を前提としていたため修正
```

**水平展開なしの場合:**
```
Required: No
Details: 本指摘は本棚画面固有のUI仕様に関するものであり、他画面には該当する実装パターンが存在しない。
```
