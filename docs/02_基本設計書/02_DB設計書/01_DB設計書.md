# DB設計書

## 1. 概要
本ドキュメントは、Web小説リーダー「Yommy」で使用するローカルデータベース（Room）の設計を定義する。

## 2. データベース構成
SQLite (Room Persistence Library) を使用し、以下のテーブルで構成する。

### 2.1. Novels テーブル（作品管理）
作品の基本情報と読書状態を管理する。

| カラム名 | 型 | 説明 |
| --- | --- | --- |
| `id` | String | 作品ID（カクヨム/なろうの作品ID、主キー） |
| `source_url` | String | 作品のトップページURL |
| `title` | String | 作品タイトル |
| `author` | String | 作者名 |
| `genre` | String | ジャンル（検索・ランキング取得時にスクレイピング） |
| `synopsis` | String | あらすじ（検索・ランキング結果表示用） |
| `tags` | String | タグ一覧（JSON配列形式: `["tag1", "tag2"]`） |
| `total_chapters` | Int | 未読チェック用の最新総話数 |
| `site_updated_at` | Long | サイト側での最終更新日時（作品トップページの更新情報から取得、表示用） |
| `last_read_episode_id` | Long | 最後に読んだ話のID（`Episodes.id` を参照） |
| `last_read_position` | String | 最後に読んだ位置（HTMLの段落IDやインデックス） |
| `site_source` | Enum | サイト識別（`KAKUYOMU`, `NAROU` 等） |
| `created_at` | Long | 本棚への登録日時 |
| `updated_at` | Long | ローカルDB上での最終更新日時 |

### 2.2. Episodes テーブル（キャッシュ・目次）
各話の目次情報および本文キャッシュを管理する。

| カラム名 | 型 | 説明 |
| --- | --- | --- |
| `id` | Long | 一意識別子（主キー、AutoIncrement） |
| `novel_id` | String | 紐づく作品のID（外部キー: `Novels.id`） |
| `url` | String | 話のURL（ユニーク制約） |
| `title` | String | エピソードタイトル（サブタイトル） |
| `index_order` | Int | 作品内での話数順序（1から開始） |
| `content_html` | String | 本文HTML（キャッシュデータ、未取得時はNULL、最大1MB） |
| `last_fetched_at` | Long | サーバーから取得・更新した日時 |

## 3. インデックス・制約
- `Episodes.novel_id` には `Novels.id` への外部キー制約（ON DELETE CASCADE）を設定する。
  - **注意**: 作品削除時は画面設計書（SC-001）の確認ダイアログで「キャッシュも削除されます」と明示する。
- `Episodes` テーブルには `(novel_id, index_order)` の複合ユニークインデックスを付与し、話数の重複登録を防止する。
  - `url` カラムは参照用のみで、ユニーク制約は付与しない（サイト側のURL変更に対応）。
- `Novels.id` と `Episodes.novel_id` をキーとした検索が頻繁に行われるため、適切にインデックスを配置する。

## 4. 検索・ランキングキャッシュ

### 4.1. SearchCache テーブル（検索・ランキング結果のキャッシュ）
検索結果やランキング情報を一時的にキャッシュし、サーバー負荷を軽減する。

| カラム名 | 型 | 説明 |
| --- | --- | --- |
| `id` | Long | 一意識別子（主キー、AutoIncrement） |
| `cache_key` | String | キャッシュのキー（"ranking:総合" や "search:keyword" 等） |
| `novel_id` | String | 作品ID（カクヨム/なろうの作品ID） |
| `title` | String | 作品タイトル |
| `author` | String | 作者名 |
| `genre` | String | ジャンル |
| `synopsis` | String | あらすじ |
| `total_chapters` | Int | 総話数 |
| `site_updated_at` | Long | サイト側での最終更新日時 |
| `source_url` | String | 作品URL |
| `site_source` | Enum | サイト識別（`KAKUYOMU`, `NAROU` 等） |
| `rank_order` | Int | ランキング順位（ランキングキャッシュの場合のみ） |
| `cached_at` | Long | キャッシュ作成日時 |

**キャッシュポリシー:**
- キャッシュ有効期限: 1時間
- 期限切れのキャッシュは自動的に破棄し、新規スクレイピングを実行
- `cache_key` と `cached_at` の組み合わせで期限判定を行う

**cache_keyの命名規則:**
- ランキング: `ranking:{genre}` （例: `ranking:overall`, `ranking:fantasy`）
- 検索: `search:{URLエンコードされたキーワード}` （例: `search:%E7%95%B0%E4%B8%96%E7%95%8C`）
- ジャンルはEnumで定義し、キー生成は`CacheKeyGenerator`で一元管理する

**クリーンアップロジック:**
- アプリ起動時に1時間以上前のキャッシュを削除: `DELETE FROM SearchCache WHERE cached_at < (現在時刻 - 3600000)`
- キャッシュレコード数が1000件を超えた場合は、古いものから削除してLRU管理
- 検索実行前に該当`cache_key`の期限切れレコードを削除

## 5. 計算プロパティ（派生データ）

以下の情報はDBに保存せず、実行時に計算で導出する:

### 5.1. Episodes.is_read（既読フラグ）
- `Novels.last_read_episode_id` と比較して動的に算出
- ロジック: `episode.id <= novel.last_read_episode_id` なら既読
- データ整合性の問題を回避（ユーザーが飛ばし読みしても矛盾が発生しない）

### 5.2. Novels.has_updates（未読フラグ）
- `total_chapters`、`Episodes`の登録数、`last_read_episode_id`から動的に算出
- ロジック: `total_chapters >現在のEpisodes数` または `未読エピソードが存在` なら未読あり
- 更新チェック時の同期処理が不要になり、レースコンディションを回避

## 6. キャッシュストレージ管理

### 6.1. Episodes.content_htmlのサイズ制限
- **1話あたりの最大サイズ**: 1MB（約100万文字相当のHTML）
- 超過時の挙動: キャッシュせずオンデマンド取得（警告ログを出力）
- 実装時に`content_html.length`をチェックし、1MB超過時はNULLとして保存

### 6.2. キャッシュ総容量の上限
- **アプリ全体のキャッシュ上限**: 200MB
- 超過時の挙動:
  - LRU（Least Recently Used）アルゴリズムで古いエピソードから削除
  - `last_fetched_at`が最も古いレコードから順に削除
  - ユーザーには設定画面（SC-004-001）の「キャッシュ削除」で手動クリア可能

### 6.3. ストレージ不足時のエラーハンドリング
- DB書き込みエラー（SQLiteFullException）をキャッチ
- ユーザーに「ストレージ不足」ダイアログを表示し、キャッシュクリアを促す
- アプリがクラッシュせず安全に動作を継続

## 7. マイグレーション戦略

### 7.1. スキーマバージョン管理
- Room `@Database(version = 1)` として初期バージョンを定義
- 将来のスキーマ変更時はバージョン番号をインクリメント（v2, v3...）

### 7.2. マイグレーションスクリプト例

**v1 → v2: NovelTagsテーブル追加**
```kotlin
val MIGRATION_1_2 = object : Migration(1, 2) {
    override fun migrate(database: SupportSQLiteDatabase) {
        database.execSQL("""
            CREATE TABLE IF NOT EXISTS NovelTags (
                novel_id TEXT NOT NULL,
                tag_name TEXT NOT NULL,
                PRIMARY KEY(novel_id, tag_name),
                FOREIGN KEY(novel_id) REFERENCES Novels(id) ON DELETE CASCADE
            )
        """)
        // 既存のNovels.tagsからデータを移行
        database.execSQL("""
            INSERT INTO NovelTags (novel_id, tag_name)
            SELECT id, json_each.value
            FROM Novels, json_each(Novels.tags)
        """)
    }
}
```

**v2 → v3: last_read_positionの形式変更**
```kotlin
val MIGRATION_2_3 = object : Migration(2, 3) {
    override fun migrate(database: SupportSQLiteDatabase) {
        // 既存データをバックアップ
        database.execSQL("ALTER TABLE Novels RENAME TO Novels_old")
        // 新スキーマでテーブル作成
        database.execSQL("CREATE TABLE Novels (...)")
        // データ移行（変換ロジックを適用）
        database.execSQL("""
            INSERT INTO Novels SELECT id, ..., 
            CASE WHEN last_read_position LIKE 'paragraph_%' 
            THEN last_read_position ELSE NULL END
            FROM Novels_old
        """)
        database.execSQL("DROP TABLE Novels_old")
    }
}
```

### 7.3. 破壊的変更時の対策
- マイグレーション失敗時は`fallbackToDestructiveMigration()`を使用せず、エラーを明示的にハンドリング
- ユーザーにデータ損失の可能性を警告し、バックアップ（JSON export）機能を提供
- 将来的にはCloud Backup（Firebaseなど）との連携を検討
