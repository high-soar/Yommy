## 1. 概要
本機能は、外部小説サイト（主にカクヨム）から作品を検索またはランキング形式で取得し、アプリ内の本棚（ローカルDB）に登録することを目的とする。

> [!NOTE] 提供価値
> - アプリ内で完結するシームレスな作品探し体験を提供する。
> - ユーザーはWebブラウザを行き来することなく、気に入った作品を即座に「本棚」に追加できる。

## 2. クラス・ファイル構成

MVVMアーキテクチャに基づき、以下のクラスで構成する。

| **ViewModel** | `SearchViewModel.kt` | UI状態（検索結果、ローディング、エラー）の管理、Repositoryの呼び出し。 |

| **Repository** | `SearchRepository.kt` | 検索・ランキングデータの取得（キャッシュ or スクレイピング）を管理。 |

| **DataSource** | `KakuyomuScraper.kt` | HTML解析（Jsoup使用）、検索結果・ランキング情報の抽出。 |
| **DAO** | `SearchCacheDao.kt` | 検索キャッシュ（`SearchCache`テーブル）へのアクセス。 |

## 4. イベント・関数詳細

### 4.1. ViewModel: `SearchViewModel`

| 関数名 | 引数 | 戻り値 | 処理概要 |
| :--- | :--- | :--- | :--- |
| `switchTab` | `tab: SearchTab` | `Unit` | タブを切り替える。 |
| `updateGenre` | `genre: Genre` | `Unit` | ランキングのジャンルを変更し、ロード処理を開始する（ページ1リセット）。 |
| `searchNovels` | `query: String` | `Unit` | キーワード検索を実行する（ページ1リセット）。 |
| `loadMore` | なし | `Unit` | 現在のアクティブタブに応じて追加ページを読み込む。 |
| `registerNovel` | `item: SearchResultItem` | `Unit` | 指定された作品を本棚（`Novels`テーブル）に登録する。 |
| `updateRegisteredState` | なし | `Unit` | `NovelRepository`を監視し、`registeredNovelIds`を更新する。 |

#### 詳細ロジック

**`fetchRanking(genre: Genre, page: Int)` (private/internal called by init & updateGenre)**
1. `_uiState` を更新: `isLoading = true`
2. `searchRepository.getRanking(genre, page)` を呼び出す。
    - **キャッシュ戦略**:
        - 原則: キャッシュ有効期限内ならキャッシュ（DB）から取得。
        - 期限切れまたはキャッシュなしならスクレイピング実行。
        - **例外**: スクレイピング失敗（オフライン等）時、期限切れでもキャッシュが残っていればそれを使用する（Fail-Safe）。
3. 取得結果で `_uiState` の `rankingList` を更新（page=1なら置換、page>1なら追加）。
    - 取得件数が0件なら `hasMoreRanking = false` に設定。
4. `isLoading = false`。
5. エラー時（スクレイピング失敗かつキャッシュなし）は `errorMessage` に「ランキングの取得に失敗しました」等を設定。

**`registerNovel(item: SearchResultItem)`**
1. 楽観的UI更新はView側で行うか、Stateに一時的な登録済みフラグを持たせる（今回は`registeredNovelIds`即時更新で対応）。
2. `Novel` オブジェクトを生成（`id`, `title`, `author`, `synopsis` 等をマッピング）。
3. `viewModelScope.launch` で `novelRepository.addNovel(novel)` を実行。
   - `INSERT ON CONFLICT IGNORE` により重複登録を防止。
4. 成功後、最新の `registeredNovelIds` を再取得（Flow監視していれば自動更新）。
5. 失敗時（DBエラー等）は `errorMessage` を表示し、登録状態をロールバック。

## 5. データベース・API アクセス

### データベース (Room)

#### `SearchCache` エンティティ
```kotlin
@Entity(tableName = "search_cache", primaryKeys = ["type", "query", "page", "orderIndex"])
data class SearchCache(
    val type: String, // "RANKING" or "SEARCH"
    val query: String, // genreSlug or searchKeyword
    val page: Int,
    val orderIndex: Int, // 並び順保証用
    val novelId: String,
    val title: String,
    val author: String,
    val synopsis: String,
    val lastUpdatedAt: Long // データ取得時刻（キャッシュ有効期限判定用）
)
```

#### `SearchCacheDao`
- `findByCacheKey(type: String, query: String, page: Int): List<SearchCache>`: キャッシュ取得（orderIndex順）。
- `insertAll(list: List<SearchCache>)`: 検索結果の一括保存。
- `deleteByCacheKey(key: String)`: 特定キーのキャッシュ削除（更新前）。
- `deleteExpired(threshold: Long)`: 期限切れキャッシュの削除。

#### `NovelDao` (既存)
- `getNovelIds(): Flow<List<String>>`: 登録済み作品ID一覧の監視用。
- `insert(novel: Novel)`: 作品登録。

### スクレイピング (`KakuyomuScraper`)

- **使用ライブラリ**: Jsoup, OkHttp
- **アクセス制御**: `OkHttp` の `Interceptor` または `Repository` 層で、同一ホストへのリクエスト間隔（最低3秒）を保証する。

**`search(keyword: String): List<SearchResultItem>`**
- URL: `https://kakuyomu.jp/search?q={keyword}`
- 解析対象: 検索結果リスト（`.widget-work` 等のクラス）。

**`getRanking(genre: Genre, page: Int): List<SearchResultItem>`**
- URL: `https://kakuyomu.jp/rankings/{genre.urlSlug}?page={page}`
- 解析対象: ランキングリスト。

## 6. エラーハンドリング・境界値

| ケース | 挙動 | ユーザーへのフィードバック |
| :--- | :--- | :--- |
| **オフライン** | キャッシュがあれば「キャッシュ表示中」として表示。キャッシュもなければリトライボタン表示。 | スナックバーまたは画面中央メッセージ。 |
| **スクレイピング失敗** | サイト構造変更の可能性。ログ出力し、Webビューへのフォールバックを提案。 | ダイアログ：「データの取得に失敗しました。Webで開きますか？」 |
| **検索結果0件** | `searchList` を空リストで更新。 | エンプティステート：「検索結果が見つかりませんでした」。 |

> [!TIP] 実装のポイント
> - **画像の扱い**: 検索結果に書影がある場合でも、データ通信量削減のため今回は取得・表示しない（テキストベースのリストとする）。
> - **非同期処理**: スクレイピングはネットワークI/Oを含むため、必ず `Dispatchers.IO` で実行する。
