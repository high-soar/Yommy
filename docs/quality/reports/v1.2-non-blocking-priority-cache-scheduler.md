## 6. プロセス・ガイドライン・スキル改善アクション（Kaizen 5 施策）

`v1.2` で検出された非同期スケジューラ競合・キュー状態整合・親子分離漏れ・TypeScript / Playwright 検証盲点・双方向トレーサビリティ不備の再発を恒久防止するため、[docs/guidelines/testing.md](../../guidelines/testing.md)（`§3.10`）および [.github/skills/c-ut-workflow/SKILL.md](../../../.github/skills/c-ut-workflow/SKILL.md) へ以下の **5 施策** を反映しました。

1. **`CacheScheduler` 複数 `await` 初期化のエポック・直列化ガード、保存後クリーンアップ完遂、および優先度跨ぎ 1.5 秒レート制限（`No. 453, 454, 456, 458, 473, 477, 483`: `R1-12, R1-16, R1-22` 再発防止）**:
   - `enqueueBatchCache` のように DB 参照・登録が複数 `await` に跨る非同期起動処理では、開始時世代スナップショット（`globalCancelEpoch` / `novelCancelEpochs`）および未完了投入の直列化・待機追跡（`pendingEnqueues`）を必須とし、`pauseNovelTasks`・`cancelNovelTasks`・`cancelAllTasks`・`handleTombstoneDeletion`・`dispose` 競合後の復活起動を確実に遮断すること。
   - `chapterRepository.saveChapterBody` 保存完了後は中断判定（`signal.aborted`）に関わらず `queueRepository.deleteByNovelAndChapters` と進捗確定（`markChapterCompletedInBatch`）を必ず完遂させ、全優先度共通の通信完了時刻（`lastNetworkRequestCompletedAt`）で低優先度の 1.5 秒レート制限を維持すること（`activeLowSleeping` 中の `high`/`medium` 0ms 割り込みは許容）。
2. **失敗キュー（`'failed'`）永続保護・排他世代カウンタ・アンマウント非依存再開・高優先度 `AbortSignal` 伝播（`No. 452, 460, 461, 462, 472, 474, 475, 476, 484`: `R1-01, R1-11, R1-13, R1-14, R1-15, R1-23` 再発防止）**:
   - バッチ完了時のキュー整理は `clearCompletedQueueRows` により既存の未キャッシュ `'failed'` 行を保護しつつ非 `'failed'` 行を無条件削除し、手動再試行は上限なしで再挑戦を許可する一方、`refreshToc` 等の自動再開時は `'failed'` 行を自動再投入から除外して進捗表示上の失敗件数を正確に維持すること。
   - `useNovelDetail` の排他操作（`refreshToc` / `confirmDeleteNovel` / `confirmClearCache` / `reloadDetail`）開始時は `progressSyncSeqRef` を加算し、`isAnyExclusiveOperationActive` と合わせて古い進捗同期の上書きを遮断すること。また `refreshToc` の通信失敗や `SCR-02` アンマウント時でも DB ベースの `resumePausedBatchCacheIfNeeded` で停止中バッチを確実に再開すること（UI State 更新のみ `runIfMounted` 保護）。
   - `useWebViewImport.importCapturedDomInternal` の完了通知（`onImportComplete`）には `isMountedRef.current` ガードを適用し、`useReader` のオンデマンド `'high'` 本文取得には `chapterFetchAbortControllerRef` / `stopChapterFetch()` による `AbortSignal` 伝播を実装すること。
3. **親コンポーネント単体テストの `.mockImplementation(() => null)` 完全分離・非同期初期化待機・`afterEach(vi.restoreAllMocks)` 徹底（`No. 466, 467, 489`: `R1-05, R1-06` 再発防止）**:
   - Container / Page 等の親テストで直下の子コンポーネントに `vi.spyOn` を適用する際は `.mockImplementation(() => null)` を徹底し、子・孫コンポーネントの実描画、子 `data-testid` 探索、および子側タイマー（`setTimeout` 等）への依存を排除して Props / コールバック配線のみを検証すること。
   - 非同期初期化を伴う Hook / Provider 単体テストでは `waitFor` により初期設定・認証状態の安定完了を確認してからフォールバック分岐を検証し、`vi.spyOn` を使用する全テストファイルの冒頭（describe 先頭等）へ `afterEach(() => { vi.restoreAllMocks(); })` を統一配置すること。
4. **`tsconfig.app.json` による `test/` 常時型検査、Playwright ワークツリー排他ポート分離、および全画面遷移直後の `isReady` 待機（`No. 465, 479, 481, 482, 485, 488`: `R1-04, R1-18, R1-20, R1-21, R1-24` 再発防止）**:
   - `tsconfig.app.json` の `"include"` に `"src"` と `"test"` の双方を維持して `npm run typecheck` で E2E テストや Repository 戻り値型変更（`ChapterSummary` と `ChapterRecord` の差異など）を常時検知し、IT でも `byteSize > 0` や `getChapter` の `bodyHtml.length > 0` 等の実在フィールドで検証すること。
   - `playwright.it.config.ts` / `playwright.vrt.config.ts` は `process.cwd()` の FNV-1a ハッシュによるワークツリー固有ポートと `reuseExistingServer: false` で並列実行時のサーバー競合を遮断し、IT 内のすべての `page.goto(...)` および `page.reload()` 直後に `waitForServicesReady(page)`（`typeof window.__yommyServices !== "undefined" && window.__yommyServices.isReady === true`）の待機を義務付けること。
5. **PR クローズ前 1 対 1 仕様・契約・双方向トレーサビリティ完全照合（`No. 463, 464, 471, 478, 480, 486, 487`: `R1-02, R1-03, R1-10, R1-17, R1-19, R1-25, R1-26` 再発防止）**:
   - 実装完了後は変更モジュールの Hook Options / Result 型、`db-schema.md` の状態遷移・削除条件、公開エクスポート型名、および `requirements.md`（`SYS-REQ-xx`）と各機能仕様書（`AC-xx` / `related_specs` / `related_tests`）の双方向対称性を 1 対 1 で照合してからレビューへ進めること。
