> 本シートは、Step 3 結合テスト（IT）工程において AI が作業中（Playwright 実ブラウザ IT 自動テスト作成・実行、静的検証、AI レビュー）に確認した不備を記録するための専用ファイルです。
> C・UT 工程で確立された「スリム化必須6項目」標準に基づき、タスク進行中は開発リズムを損なわないよう以下の 6 項目で記録します。
> 既存成果物の仕様違反、契約違反、再現可能な誤動作、レビュー指摘により確定した不備を 1 件として記録します。同一原因の連鎖的失敗は 1 件に集約します。
> また、**原因分類が `D`（設計・仕様誤認）である場合は、コード・テストの修正のみで済ませることを厳禁とし、必ず関連設計書（ED/ID/OpenAPI）の同期是正コミット・PR をセットで記録**します。

## 運用ルールと分類凡例

### 記録必須6項目

| 項目名                   | 説明                                                                                                                                                     |
| :----------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **No.**                  | 当該タスク内での連番（1, 2, ...）                                                                                                                        |
| **検出手段**             | 不備が最初に確認された手段（例: `IT自動テスト`, `AIレビュー`, `手動ブラウザ検証`, `静的検査` 等）                                                        |
| **成果物区分**           | `製品コード` または `テスト・モック等支援成果物`                                                                                                         |
| **対象箇所**             | 不備が存在したファイル名・関数名・モジュール名                                                                                                           |
| **原因分類**             | 原因分類コード（L / S / D / B / A）                                                                                                                      |
| **不備の概要と是正内容** | 不備の具体的な現象・根本原因、およびどのように是正したか（コミットリンク・PRリンクを含む）。**原因分類 D の場合は設計書同期コミット・PR も併記すること** |

### 原因分類コード（5分類）

- **L (Logic)**: ロジック誤り（条件分岐ミス、ループ誤り、真偽値反転、フィルタリング条件誤り、URL パラメータパースミス）
- **S (State)**: 状態遷移誤り（React state 更新漏れ、Context 値の不整合、ブラウザ履歴・URL クエリ同期ミス、Dirty State 制御ミス）
- **D (Design)**: 設計・仕様誤認（OpenAPI 契約や ED/ID 設計書の見落とし、パス・パラメータ・型不一致、認可権限誤認、シードデータ不整合）
- **B (Boundary)**: 境界値未考慮（`null` / `undefined` の考慮漏れ、空文字・空配列、最大文字数超過、Unicode サロゲートペア）
- **A (Async)**: 非同期制御不備（Promise ハンドリング漏れ、`AbortController` 未連携、Race Condition、遅延レスポンス上書き）

### 成果物区分の定義

- **製品コード**:
  `src/` 配下のプロダクションコード（画面、フック、コンポーネント、ルーター、API クライアント等）に存在した不備。
  先行する C・UT 工程の品質を測る「単体テスト欠陥除去率（$\text{DRE (UT)}$）」の算定対象（分母）となります。
- **テスト・モック等支援成果物**:
  結合テストコード（`test/it/`）、Playwright 設定（`playwright.it.config.ts`）、MSW ハンドラー・データストア（`src/mocks/`）、Storybook、設定等の不備。
  製品コードのバグ密度や DRE を歪めないよう別集計とし、製品コード欠陥数には含めません。

### 原因分類 `D` 検出時の設計同期原則

原因分類 `D`（設計・仕様誤認）として検出された不備については、以下のルールを厳守します。

1. **設計同期の義務化**: コードやテストの修正のみで完了とせず、該当する上流成果物（`docs/ed/`、`docs/id/`、`docs/ed/api/openapi.yaml`、`docs/rd/` 等）を必ず同時に修正します。
2. **トレーサビリティの記録**: 是正内容欄に、コード修正コミットだけでなく上流設計書の修正コミットまたは PR 番号を必ず記載します。
