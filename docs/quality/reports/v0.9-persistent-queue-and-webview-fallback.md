# Milestone `v0.9`（永続ダウンロードキュー ＆ 内蔵WebViewインポート）品質分析・振り返りレポート（Kaizen）

## 1. エグゼクティブサマリー（Executive Summary）

Milestone `v0.9`（Persistent Queue & WebView Fallback）では、長編小説の一括キャッシュ体験を飛躍的に安定化させる **「永続ダウンロードキュー（QueueRepository / download_queue）の実装と一括キャッシュ中断再開・失敗話再試行統合」**、およびサイト側の DOM 構造変更・Bot 対策（Cloudflare）・認証壁を人間協調で確実に突破する **「内蔵ブラウザ画面（SCR-04）と WebView 表示中 DOM 手動インポート・フォールバック遷移（TR-09〜12）」** の 2 つの親 Issue（`#268`, `#269`）を完遂した。

1. **Issue #268（永続ダウンロードキュー［QueueRepository / download_queue］の実装と一括キャッシュ中断再開・再試行統合、HO-34）**:
   - SQLite `download_queue` テーブル（`id`, `novel_id`, `chapter_index`, `status`, `retry_count`, `error_message`, `created_at`, `updated_at`）を新設し、アプリ再起動やタスクキル後もダウンロード進行状態を完全永続化（`AC-ND-24`, `AC-ND-25`）。
   - `useNovelDetail` において、未取得話一括キャッシュの開始・中断・再開（`キャッシュを再開（残りN話）`）・通信エラー時スキップ継続・失敗話再試行（`失敗した話を再試行（N話）`）、および作品/全話キャッシュ削除時のキュー自動整理を統合。
   - `SCN-04` 結合テストを拡張し、一括キャッシュ実行中の中断・再開・エラー発生時の再試行・キャッシュ削除時のキュー整合性を決定論的に検証。
2. **Issue #269（内蔵ブラウザ画面［SCR-04］と WebView 表示中 DOM 手動インポート・フォールバック遷移［TR-09〜12］の実装、HO-35）**:
   - Android ネイティブプラグイン `WebViewDomPlugin.java`（全画面 Dialog 内 WebView 展開、`evaluateJavascript` による DOM キャプチャ、安全なスキーム判定、ファイル/コンテンツアクセス遮断）および Web 側 `CapacitorWebViewDomBridge` を新設（`SYS-REQ-13`, `SYS-REQ-14`）。
   - 新画面 `WebViewImportPage`（`SCR-04`）、`WebViewImportContainer`、`useWebViewImport` を実装し、作品詳細からの「Webで開く」（`TR-09`）、小説リーダー未キャッシュ話取得エラー時の「内蔵ブラウザで開いて取り込む」（`TR-10`）、DOM インポート完了時の自動復帰・読書再開（`TR-11`）、および「← 戻る」ボタン/OS バックキーによる直前画面復帰（`TR-12`）を確立。
   - 新規結合テスト `SCN-07`（4 テストケース）を整備し、目次・本文の DOM インポート・エラー画面からのフォールバック・未登録作品保護・安全スキーム遮断・論理階層復帰のフルシナリオを E2E で担保。

これにより、Yommy の要件定義に定められた **全 7 画面（`SCR-01`〜`SCR-07`）** および **全 20 システム要件（`SYS-REQ-01`〜`SYS-REQ-20`）** の全スコープがすべて本番実装・テスト・仕様化され、完全コンプリートを達成した。

全機能 PR マージ後、**Issue #270（Milestone `v0.9` 全体横断レビュー・品質分析・完了承認）** において、独立横断レビュー **Round 1（`R1-01`〜`R1-22`：Sub-issue `#309` / PR `#310`）** および **Android 実機検証（`HO-34`, `HO-35` 完了精算 ＆ Sub-issue `#311` / PR `#312`）** を実施した。
検出された全 27 件の不備・指摘（WebView インポート時の作品 URL/話数照合漏れによる別作品上書きリスク `R1-01`、Android ネイティブ `domCaptured` リスナー配線 `R1-10`、アンマウント時 Bridge クリーンアップ `R1-11`、ネイティブ WebView セキュリティ遮断 `R1-20`、一括キャッシュ実行中の失敗件数リアルタイム表示 `No. 306` 等）を AI 自律マージにて完全収束させ、全自動テスト（UT 2,003 件 / カバレッジ 100%、VRT 518 件、IT 22 件）の PASS を達成した。

## 6. 次期マイルストーンへ向けたプロセス・スキル改善（Kaizen）

Milestone `v0.9` で得られた知見と再発防止策を、リポジトリ正本ガイドライン（`docs/guidelines/testing.md`）および AI スキル（`.github/skills/c-ut-workflow/SKILL.md`）へ直接アップデートした。

### 6.1 反映された 5 つの再発防止規律

1. **WebView DOM インポートにおける作品 URL 照合・エピソード一致検証と画面離脱保護（No. 284, 294, 295: `R1-01`, `R1-11`, `R1-12` 再発防止）**:
   - `useWebViewImport` において、`canonicalUrl` の作品 URL 完全一致検証と話数解決の安全ガード（見つからない場合の安全エラー）、アンマウント時フラグ `isMountedRef` による画面離脱時の非同期 State 更新遮断および Bridge クリーンアップ（`close()`）呼び出し、`httpClient` 未渡下時の non-null アサーション排除と防御的フォールバックを規定。
2. **Android ネイティブプラグインのセキュリティ強化とライフサイクル連動破棄（No. 293, 303: `R1-10`, `R1-20` 再発防止）**:
   - `WebViewDomPlugin.java` において、ローカルファイルおよび Content URI への不正アクセスを遮断する `setAllowFileAccess(false)`, `setAllowContentAccess(false)` の明示的設定、URL スキームの大文字小文字非依存判定、および Dialog 閉鎖時・破棄時の WebView インスタンス解放（`destroy()`）と JavaScript リスナー（`domCaptured`）の確実なバインド・クリーンアップを規定。
3. **一括キャッシュ進行中の失敗件数リアルタイム表示と前回の失敗状態クリア（No. 287, 306: `R1-04` 再発防止）**:
   - 一括キャッシュ実行中に通信エラー等で各話取得失敗が発生した場合、ヘッダーの進捗表示に `[失敗 N話]` を警告色（アンバー）で即座にリアルタイム反映し、裏で失敗しているにもかかわらず正常進行しているように見える UX 誤認を防止。さらに `startBatchCache` 実行開始時に前回の失敗状態（`failedCacheCount`, `failedChapterIndexes`）を確実にリセットし、再試行時に誤った失敗数が残存しない状態管理規律を確立。
4. **結合テスト（IT）における固定待機排除と状態駆動（`expect.poll`）アサーション（No. 292: `R1-09` 再発防止）**:
   - 非同期永続化（SQLite 一括キャッシュ、再試行、ダウンロードキュー更新）を検証する E2E 結合テストにおいて、固定ミリ秒待機（`page.waitForTimeout` 等）による flake を排除し、`expect.poll` による決定論的状態収束待ち（キュー空、ステータス変更）を義務化。
5. **UI コンポーネント単体テストにおける親子分離の徹底（No. 297: `R1-14` 再発防止）**:
   - 複数画面共通の下部タブバー（`BottomTabBar`）等の子コンポーネントを配置する親コンポーネントのテストにおいて、不要な隠し要素（`browser-go-button` 等）による裏技的テストを排除し、親は「子コンポーネントへの Props 配線（`currentTab="browser"` 等）」のみを検証する親子分離規約を徹底。
