## 1. 画面構成の基本方針

1. **スコープの準拠と Next.js App Router への移行**:
   - [docs/rd/step3.md](../rd/step3.md) および [docs/ed/01-system-overview.md](01-system-overview.md) に基づき、Step 2 で確立した全 6 画面（ログイン、ダッシュボード、一覧、詳細、新規起票、ユーザー・プロジェクト管理）の業務機能・UI・振る舞いを 100% 維持した上で、Next.js (App Router) のファイルベースルーティング（`/login`, `/dashboard`, `/tickets`, `/tickets/new`, `/tickets/[id]`, `/admin/management`）へ移行します。
   - ルートパス（`/`）からの認証状態に応じたリダイレクト（未認証時は `/login`、認証済み時は `/dashboard`）、`/admin` から `/admin/management` へのリダイレクト、および未定義パスに対する共通 404（`not-found.tsx`）を網羅します。
2. **ロールと責務分離（SoD: Separation of Duties）**:
   - 一般ユーザー（業務運用担当）と管理者ユーザー（システム管理・監査）のロールを分離し、画面単位および画面内コンポーネント単位で閲覧・操作権限を厳密に制御します。
3. **プロジェクト制によるデータ分離と横断管理**:
   - チケットおよびユーザーをプロジェクトに紐づけ、一般ユーザーは自プロジェクト範囲の業務に専念し、管理者は全社プロジェクト横断でのモニタリング・設定を行える画面構成とします。
4. **共通ナビゲーション（開閉式サイドバー）**:
   - 保護された画面（`/dashboard`, `/tickets`, `/tickets/new`, `/tickets/[id]`, `/admin/management`）において、統一された操作導線として開閉トグル付きサイドバーを常設します。各メニュー項目のリンク先 URL を Next.js App Router 構成へ整合させ、開閉状態の `localStorage` 永続化およびモバイル幅でのオーバーレイドロワー対応を行います。
5. **関心の分離と共通状態・404 の切り分け**:
   - 認証、サマリー、一覧、詳細、新規起票、管理の各画面の責務を分離し、すべての保護された画面でローディング・空状態・エラー・処理中・権限エラー（403）を統一的に設計します。
   - 未定義パスに対する Next.js 共通 404（`not-found.tsx`）と、動的ルート `/tickets/[id]` におけるデータ未存在時の詳細画面内 404 を明確に切り分けて設計します。

## 3. 各画面の概要仕様

### 3.1 SCR-AUTH: ログイン画面

- **画面目的**:
  - 利用者の身元を認証し、ロール（一般ユーザー / 管理者ユーザー）に応じたセッションを確立してアプリケーションへの安全なアクセスを提供する。
- **Next.js ルートパス**:
  - `/login`（`src/app/login/page.tsx`）
- **対象ロール**:
  - 未認証ユーザー（ログイン後は各ロールの初期画面である SCR-00 ダッシュボード `/dashboard` へ自動遷移）。
  - ※認証済みユーザーが直接 `/login` へアクセスした場合は、自動的に `/dashboard` へリダイレクトする。
  - ※未認証ガード（Auth Guard）によって `?redirect=` クエリ付きで遷移してきた場合は、認証成功後にその指定パスへ復帰遷移する。
- **主要な表示項目**:
  - 認証入力フォーム部:
    - ユーザー名入力フィールド
    - パスワード入力フィールド
    - ログインボタン
  - ガイダンス・付帯情報部:
    - モック認証の入力例案内・プレースホルダー（一般ユーザー例: `user1`, `user2` / 管理者例: `admin`）
    - エラーメッセージ表示エリア（入力未済バリデーション、認証失敗エラー）
- **主要な操作**:
  - ユーザー名・パスワードの入力
  - ログインボタン押下（認証 API 実行とセッション開始）
- **画面状態とフィードバック**:
  - **初期表示**: 入力フォームが初期フォーカスとともに表示される。
  - **入力エラー**: ユーザー名またはパスワードが空の場合のバリデーションメッセージ表示。
  - **認証処理中（Submitting）**: ログイン処理中のローディング表示、二重送信防止のためのボタン非活性化。
  - **認証失敗（Error）**: ユーザー名またはパスワードの不一致時に「ユーザー名またはパスワードが正しくありません」と表示。
- **対応する要件・受け入れ条件**:
  - [docs/rd/step3.md#21-ルーティングとコンポーネント移行方針](../rd/step3.md#21-ルーティングとコンポーネント移行方針)
  - [docs/ed/01-system-overview.md#51-システム受け入れ条件一覧](01-system-overview.md#51-システム受け入れ条件一覧) の `SYS-AC-08`, `SYS-AC-09`, `SYS-AC-15`

### 3.2 SCR-00: ダッシュボード画面

- **画面目的**:
  - ログイン後のポータル画面として、利用者のロールに応じた重要指標・案件サマリーを俯瞰させ、直感的な状況把握と次の業務アクション（担当チケットへの着手等）へのクイックアクセスを提供する。
- **Next.js ルートパス**:
  - `/dashboard`（`src/app/(authenticated)/dashboard/page.tsx`）
  - ※ルート URL（`/`）への認証済みアクセス時のリダイレクト先。
- **対象ロール**:
  - 一般ユーザー、管理者ユーザー（ロールに応じて表示コンポーネントが完全に分岐）。
- **主要な表示項目**:
  - **一般ユーザー表示時**:
    - 所属プロジェクト名表示
    - ステータス別チケット件数サマリーカード（未対応件数、対応中件数、完了件数）
    - 自分宛て担当チケット一覧（直近の担当チケットリスト、タイトル、ステータス、起票日）
  - **管理者ユーザー表示時**:
    - 全社横断総チケット件数・ステータス集計サマリーカード
    - プロジェクト別チケット件数・稼働サマリーテーブル（プロジェクト名、総件数、未対応、対応中、完了）
    - 未割り当て案件・滞留案件アラート一覧（担当者未設定または長期未完了のチケットリスト）
- **主要な操作**:
  - サマリーカードまたは滞留アラートのクリック（該当ステータス・プロジェクト条件で絞り込まれた SCR-01 問い合わせ一覧画面 `/tickets?status=<ステータス>&projectId=<ID>` へ遷移）
  - 自分宛て担当チケット一覧行のクリック（該当チケットの SCR-02 問い合わせ詳細画面 `/tickets/[id]` へ直接遷移）
- **画面状態とフィードバック**:
  - **初期読み込み中（Loading）**: 各種集計およびチケット取得 API 実行中のスケルトン/スピナー表示。
  - **データ 0 件（Empty）**: 自プロジェクトチケットなし、担当チケットなし、または全社案件なし時の空状態ガイダンス表示。
  - **API エラー（Error）**: ダッシュボード集計情報取得失敗時のエラーメッセージと再試行ボタン。
- **対応する要件・受け入れ条件**:
  - [docs/rd/step3.md#21-ルーティングとコンポーネント移行方針](../rd/step3.md#21-ルーティングとコンポーネント移行方針)
  - [docs/ed/01-system-overview.md#51-システム受け入れ条件一覧](01-system-overview.md#51-システム受け入れ条件一覧) の `SYS-AC-11`, `SYS-AC-15`

### 3.3 SCR-01: 問い合わせ一覧画面

- **画面目的**:
  - 社内の問い合わせ状況を検索・絞り込み・ソート・ページネーションによって探索し、目的のチケットを特定する。
- **Next.js ルートパス**:
  - `/tickets`（`src/app/(authenticated)/tickets/page.tsx`）
- **対象ロール**:
  - 一般ユーザー: 自プロジェクト（複数所属時は所属プロジェクト横断・絞り込み可能）に紐づくチケットのみ閲覧・検索。
  - 管理者ユーザー: 全社プロジェクト横断の全チケットを閲覧・検索（全社プロジェクト絞り込みフィルターを利用可能）。
- **主要な表示項目**:
  - 検索・絞り込み条件入力部:
    - プロジェクトフィルター（管理者: 全社プロジェクトから選択。一般ユーザー: 単一所属時は自プロジェクト固定表示/非表示、複数所属時は「自所属すべて」および自所属プロジェクト間での絞り込みが可能）
    - ステータスフィルター（全件、未対応、対応中、完了 等）
    - 担当者フィルター（全件、各担当者、未割り当て 等）
    - タイトル検索入力欄（部分一致）
    - 起票日フィルター（期間指定、クリア）
  - 表示制御・付帯情報部:
    - 表示件数選択プルダウン（10件、20件、50件）
    - 該当件数表示
    - ページネーションコントロール（前へ、次へ、最初へ、最後へ、ページ番号情報）
  - 問い合わせ一覧テーブル:
    - チケット ID（ソート可）
    - プロジェクト名（ソート可）
    - タイトル（ソート可）
    - ステータス（ソート可）
    - 担当者名（ソート可）
    - 起票者名
    - 起票日時（既定降順ソート可）
- **主要な操作**:
  - プロジェクトフィルターの変更（複数所属の一般ユーザー、または管理者）
  - ステータス・担当者フィルターの選択・変更
  - タイトルキーワード入力と検索
  - 起票日の期間指定とクリア
  - 表示件数・ソート順の変更、ページネーション操作
  - 問い合わせ行またはタイトルのクリック（SCR-02: 問い合わせ詳細画面 `/tickets/[id]` への遷移）
- **画面状態とフィードバック**:
  - **初期読み込み中**: 一覧取得 API 実行中のローディング表示。
  - **絞り込み結果 0 件**: 条件に該当する問い合わせが存在しない旨の空状態メッセージ。
  - **API エラー**: 一覧取得失敗時のエラーメッセージと再試行案内。
- **対応する要件・受け入れ条件**:
  - [docs/rd/step3.md#21-ルーティングとコンポーネント移行方針](../rd/step3.md#21-ルーティングとコンポーネント移行方針)
  - [docs/ed/01-system-overview.md#51-システム受け入れ条件一覧](01-system-overview.md#51-システム受け入れ条件一覧) の `SYS-AC-01`, `SYS-AC-02`, `SYS-AC-05`, `SYS-AC-07`, `SYS-AC-15`

### 3.4 SCR-02: 問い合わせ詳細画面

- **画面目的**:
  - 個別チケットの背景・本文・コメント履歴を確認し、業務担当者がステータスや担当者の更新、コメント追加を行う。管理者は監査目的で詳細と履歴を閲覧する。
- **Next.js ルートパス**:
  - `/tickets/[id]`（`src/app/(authenticated)/tickets/[id]/page.tsx`、動的ルートパラメータ `[id]`）
- **対象ロール**:
  - 一般ユーザー: 閲覧 ＋ **操作可能**（ステータス/担当者更新、コメント追加）。
  - 管理者ユーザー: **閲覧専用（Read-only）**（ステータス/担当者更新フォームおよびコメント投稿フォームは非表示または非活性）。
- **主要な表示項目**:
  - 問い合わせ基本情報部:
    - チケット ID
    - 所属プロジェクト名
    - タイトル
    - 起票者名
    - 起票日時
    - 本文・問い合わせ内容
  - ステータス・担当者更新部:
    - 一般ユーザー: 現在のステータス/担当者表示、変更用セレクター、更新保存ボタン
    - 管理者ユーザー: 現在のステータス/担当者のテキスト表示（更新用セレクター・ボタンは非表示）
  - コメント履歴部:
    - コメント一覧（投稿者名、所属/ロール、投稿日時、本文）の時系列表示
  - コメント投稿フォーム部:
    - 一般ユーザー: コメント入力テキストエリア、送信ボタン、文字数カウンター
    - 管理者ユーザー: 非表示（または「管理者ロールは閲覧専用のためコメント投稿はできません」メッセージ）
  - 導線:
    - 問い合わせ一覧画面（`/tickets`）へ戻るボタン
- **主要な操作**:
  - ステータス・担当者の変更と保存実行（一般ユーザーのみ）
  - コメントの入力と投稿実行（一般ユーザーのみ）
  - 一覧画面へ戻る操作（SCR-01 `/tickets` への遷移。直前の絞り込みクエリパラメータを保持・復元）
- **画面状態とフィードバック**:
  - **初期読み込み中**: 詳細・コメント取得中のローディング表示。
  - **該当チケット未存在（詳細画面内 404）**: 存在しないチケット ID（例: `/tickets/9999`）へのアクセス時は、共通 404 画面ではなく本詳細画面のコンテキスト内で「指定された問い合わせは見つかりませんでした」というエラーメッセージを表示し、一覧画面（`/tickets`）へ安全に戻るナビゲーション導線を提供する。
  - **未定義パスとの切り分け**: チケット ID が不正な階層（例: `/tickets/123/extra`）や未定義のパスへアクセスした場合は、Next.js 共通 404 画面（`not-found.tsx`）が表示される。
  - **更新・投稿中（Submitting）**: 処理中インジケーター表示、二重送信防止の非活性化。

## 4. 共通ナビゲーション仕様（開閉式サイドバー）

保護された画面（SCR-00 `/dashboard`, SCR-01 `/tickets`, SCR-02 `/tickets/[id]`, SCR-03 `/tickets/new`, SCR-04 `/admin/management`）において、画面左側に開閉式サイドバーナビゲーションを配置し、統一された業務画面レイアウトを提供します（ログイン画面 SCR-AUTH はサイドバーなしのスタンドアロン配置）。

### 4.1 全体構造とレイアウト

サイドバーは上部（システムブランド・開閉トグル）、中央部（ロール別メニュー項目）、下部（ユーザー情報・ログアウト）の 3 領域で構成されます。
ヘッダーおよびサイドバーはビューポート内に常時固定配置され、チケット一覧などメイン領域が縦長に伸長した場合でも、下部のユーザー情報・ログアウトボタンが画面最下部へ押し下げられることなく常にファーストビューに保持され、メインコンテンツ領域のみが独立して縦スクロールします。

```text
【一般ユーザー用サイドバー】            【管理者ユーザー用サイドバー】
┌─────────────────────────┐            ┌─────────────────────────┐
│ 社内チケット管理      [←]│            │ 社内チケット管理      [←]│
├─────────────────────────┤            ├─────────────────────────┤
│ 1. 📊 ダッシュボード     │            │ 1. 📊 ダッシュボード     │（全社横断モニタリング）
│ 2. 📋 問い合わせ一覧     │            │ 2. 📋 問い合わせ一覧     │（全社横断閲覧・監査）
│ 3. ➕ 新規起票           │            │ 3. ⚙️ ユーザー・プロジェクト管理 │（管理者専用管理）
├─────────────────────────┤            ├─────────────────────────┤
│ 👤 山田 太郎 (一般)     │            │ 👤 システム管理者 (管理者)│
│ 所属: プロジェクトA      │            │ 全社システム管理        │
│ [ログアウト]            │            │ [ログアウト]            │
└─────────────────────────┘            └─────────────────────────┘
```

### 4.2 開閉トグル動作（Expanded / Collapsed）

1. **展開状態（Expanded: 既定値）**:
   - サイドバー幅: 約 240px。
   - 上部: システム名「社内チケット管理」および折りたたみボタン `←` を表示。
   - メニュー: 各項目のアイコンとテキストラベルを明示表示。
   - 下部: ユーザー名、ロール名、所属プロジェクト名、および「ログアウト」ボタンを表示。
2. **折りたたみ状態（Collapsed）**:
   - サイドバー幅: 約 60px（レール表示）。
   - 上部: アプリアイコンおよび展開ボタン `→` を表示。
   - メニュー: アイコンのみを表示（アイコンホバー時にツールチップで画面名を表示）。
   - 下部: ユーザーアバターアイコンおよびアイコン化されたログアウトボタンを表示。
3. **トグル操作**:
   - サイドバー右上ボタン（`←` / `→`）のクリックにより、ページ再読み込みを伴わずに即時切り替え。メインコンテンツ領域の幅も連動して伸縮。

### 4.3 状態の永続化

- 開閉状態（展開/折りたたみ）はブラウザの `localStorage`（キー: `sidebar_collapsed`）に boolean 値として保存します。
- 利用者がブラウザを再読み込み（リロード）した場合や、別の保護画面へ遷移した後でも、直前の開閉状態を維持して復元します。

### 4.4 モバイル・レスポンシブ対応

- **画面幅狭小時（スマートフォン幅: 375px 以下など）の挙動**:
  - デスクトップ用サイドバーは非表示とし、メインコンテンツを画面全幅で表示。
  - ヘッダー部に「ハンバーガーメニューボタン（☰）」を配置。
  - ハンバーガーボタン押下時、サイドバーが画面左側からスライドインする「オーバーレイドロワー」として展開表示。
  - ドロワー外側の背景（半透明バックドロップ）のタップ、ドロワー内メニュー項目の選択、またはドロワー内の閉じるボタンタップにより、ドロワーを閉じて背面の画面へフォーカスを復帰。

### 4.5 メニュー項目構成（3つの枠）と Next.js リンク先

ロールごとの責務に応じて、メニュー項目を「3つの枠」に統一して配置します。リンク先 URL は Next.js App Router 構成と完全に整合させます。

| 枠順 | アイコン | メニュー項目名                        | 一般ユーザーリンク先 URL             | 管理者ユーザーリンク先 URL                        |
| :--- | :------- | :------------------------------------ | :----------------------------------- | :------------------------------------------------ |
| 1    | 📊       | ダッシュボード                        | `/dashboard`（自プロジェクト）       | `/dashboard`（全社横断モニタリング）              |
| 2    | 📋       | 問い合わせ一覧                        | `/tickets`（自プロジェクト）         | `/tickets`（全社横断＋プロジェクト絞込）          |
| 3    | ➕ / ⚙️  | 新規起票 / ユーザー・プロジェクト管理 | `/tickets/new`（自プロジェクト起票） | `/admin/management`（ユーザー・プロジェクト管理） |

### 4.6 ユーザー情報とログアウト

- サイドバー下部に、現在ログイン中のユーザー情報（表示名、ロール、所属プロジェクト）を表示。
- 「ログアウト」ボタン押下時、セッション情報を破棄して未認証状態とし、SCR-AUTH（`/login`）へ遷移。
- 編集中データ（Dirty State）が存在する場合は、画面離脱防止ダイアログによる確認を行ってからログアウトを実行。

## 6. 画面共通の状態設計方針

すべての画面において、利用者が現在のシステムの挙動を正しく認知できるよう、以下の共通状態を定義・標準化します。

1. **ローディング状態（Loading）**:
   - 初回データ取得中や API レスポンス待ちの間にインジケーター（スケルトン表示またはスピナー）を表示し、画面が操作不能または読込中であることを明示する。
2. **空状態（Empty）**:
   - 一覧の絞り込み結果が 0 件の場合、ダッシュボードの対象チケットがない場合、管理画面でデータが存在しない場合に、データが存在しない旨のガイダンスメッセージと次のアクション（「条件を変更する」「新規登録する」等）を表示する。
3. **エラー状態（Error）**:
   - ネットワーク遮断、サーバーエラー（500 系）、リクエスト不備（400 系）が発生した際に、利用者に分かりやすいエラーメッセージと再試行導線を表示する。
4. **チケット未存在エラー（詳細画面内 404）**:
   - `/tickets/[id]` にて指定された ID のチケットが存在しない（API 404）場合、SCR-02 詳細画面内で「指定された問い合わせは見つかりませんでした」というエラーメッセージと一覧画面（`/tickets`）への復帰導線を表示する。
5. **未定義パスエラー（共通 404 Not Found）**:
   - ルーティング定義外の不正な URL パスへアクセスした際、Next.js 共通の 404 画面（`not-found.tsx`）を表示し、ポータル（`/dashboard` または `/login`）への復帰導線を提供する。
6. **処理中状態（Submitting / Pending）**:
   - ログイン実行中、チケット更新中、コメント投稿中、起票登録中、管理データ更新中には送信ボタンを非活性化（ローディング表示）し、二重送信を抑止する。
7. **権限エラー状態（Forbidden / 403）**:
   - ロールで許可されていない画面や API へのアクセスが発生した際、操作をブロックし、利用者に対して権限不足である旨のフィードバックを提供した上で安全なポータル画面（`/dashboard`）へリダイレクトする。
